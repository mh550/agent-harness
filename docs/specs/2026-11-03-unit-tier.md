# The unit tier: the node evals become `node:test` files run in one process, reported into the same runner (2026-11-03)

**Goal.** Phase 1 of `docs/plans/2026-11-03-test-suite-redesign.md`. The 108 `node --input-type=module -e` evals in
35 check files each start node (27 ms) and assert by exit code. Move them into `tests/unit/<module>.test.mjs` files
under Node's built-in runner (`node --test --test-isolation=none`: one process for the whole tier), with `node:assert/strict`
assertions, reported into `tests/run.sh` as the PASS/FAIL lines it already reads, every check name unchanged so the
conformance fixture proves nothing was lost. The gain in suite CPU is small (about 3 s of 3,100); the gain is the
mechanism: a unit tier a session runs in under a second, real assertion diffs, and the place phase 4 pushes behaviours
down to. One milestone, **U1**.

**Source.** `docs/specs/2026-11-03-test-suite-redesign.md` (Phase 1); `journal/learning/2026-10-30-test-engineering.md`
entries 5, 11, 12, 15; `findings-and-research/2026-11-03-test-runner-survey.md` (`node --test`: `--test-isolation=none`
v22.8.0, custom reporters, no list-only mode); the evals themselves (`grep -c 'node --input-type=module' tests/checks/*.sh`:
51-view-pure 21, 12-journal-pure 16, 07-step-lint-pure 12, 11-deploy-guards-pure 5, 05-metrics-pure 5, 03-parked-pure 4,
02-notifications-pure 4, and 1–3 each in 28 more files); `tests/run.sh` (lines 112–139: names from `^(PASS|FAIL) `
lines, conformance against `tests/fixtures/check-names.txt`); `tests/lib.sh` `check()`.

**Rules.** `CLAUDE.md` binds: worktree only; never touch real runs or real state; fakes mirror the live API; `bash -n`,
`node --check`; one decision file per behaviour; `docs/architecture.md` and `README.md` in the same milestone. **Proceed
on the defaults written here; record them in the decision file, marked *default*; never park.** The invariant of
`docs/specs/2026-10-30-suite-time.md` holds: a tree is never marked green by anything but a green run of every check
that reads what changed in it; the unit tier is part of every full run. **Every check name survives:** the fixture

## U1 · The unit tier

### U1-01 · The reporter and the check file that carries the tier

**Choice.**

1. **`tests/unit/reporter.mjs`**, a `node:test` custom reporter (an async generator over the events, as the Node docs'
   example): on `test:pass` it yields `PASS <name>\n`, on `test:fail` `FAIL <name>\n` followed by the failure's message
   lines each indented two spaces (the `node:assert` diff, so a red is readable in the runner's output); on
   `test:diagnostic` and `test:stderr` nothing on stdout; nothing else on stdout. `<name>` is the test's own name
   (tests are flat: no `describe`, no subtests; a nested test's name would otherwise not match the fixture). *Default:* a
   reporter, not a TAP parser in bash: the TAP text's version and stability are not stated by the Node docs, the
   reporter API is Stable, and the reporter is ~15 lines.
2. **`tests/checks/00-unit-tier.sh`**: the one check file for the tier. It does not source `tests/lib.sh` (no throwaway
   project is needed) and runs, from the repo root:
   `node --test --test-isolation=none --test-reporter="$HERE/../unit/reporter.mjs" --test-reporter-destination=stdout "$HERE/../unit/*.test.mjs"`,
   prints its lines, then `N/M checks passed` from its own count of `PASS`/`FAIL` lines, exit 1 on any FAIL or a non-zero
   node exit. A node exit that is non-zero with no FAIL line (a test file that fails to import, a `process.exit` in a
   module) prints `FAIL unit tier: node --test exited <rc> with no FAIL line` so the runner's `no_fail` rule has its line.
   The file sorts first (`00-`) and is small, so under `ls -S` it starts late and costs nothing on the critical path.
3. **`tests/unit/`** holds one `<module>.test.mjs` per `lib/<module>.mjs` under test (`view.test.mjs`, `entries.test.mjs`,
   `features.test.mjs`, …), each `import { test } from "node:test"; import assert from "node:assert/strict";` and flat
   `test("<exact old check name>", () => { … })` calls. No test calls `process.exit`, writes outside `os.tmpdir()`, or
   keeps module-level mutable state (one process serves every file).
4. **The unit tier alone**: `node --test --test-isolation=none tests/unit/` (the default `spec` reporter, for a human) or
   `bash tests/run.sh 00-unit` (the suite's lines). `node --test tests/unit/features.test.mjs` runs one module's tests.
   `--test-name-pattern "<regex>"` picks tests by name.
5. **`CLAUDE.md`**: *Code rules*: "pure functions in the `.mjs` files where they can be (exported, unit-tested in
   `tests/unit/<module>.test.mjs` under `node --test`)" replaces the `node --input-type=module -e` phrase; the node
   floor "node ≥ 22.8"; *How to verify*: one sentence on the unit tier and how to run it alone. *Default:* the rule
   "every behaviour … gets a check in a `tests/checks/` file" gains "a pure function's behaviour gets a test in
   `tests/unit/`, not a stub run" (phase 4's process rules propose more; this one is the mechanism's own).

**Checks (written first)**, in `tests/checks/33-suite-runner.sh` (the runner's own file) with a throwaway `tests/unit`
directory (`TEST_UNIT_DIR`, as `TEST_CHECKS` points the runner at another checks directory; *default*: one variable, read
by `00-unit-tier.sh`): a unit file with `test("a")` passing and `test("b")` failing on `assert.equal(1, 2)` under the
reporter prints exactly `PASS a`, then `FAIL b`, then at least one line starting with two spaces holding `1` and `2`
(the diff), nothing else on stdout, exit 1; a passing-only file prints `PASS a` and exits 0; a unit file that throws at
import prints the `FAIL unit tier: node --test exited` line; `bash tests/run.sh 00-unit` on the real tree prints
`PASS`/`FAIL` lines the conformance check accepts (every name in the fixture, once); `node --check tests/unit/reporter.mjs`;
`grep -q 'node ≥ 22.8' CLAUDE.md`.

### U1-02 to U1-04 · The move, file by file

**Choice.** Three features, the eval files split between them by size (U1-02: `51-view-pure` and `12-journal-pure`;
U1-03: `07-step-lint-pure`, `11-deploy-guards-pure`, `05-metrics-pure`, `03-parked-pure`, `02-notifications-pure`, `06`,
`04`, `01`, `35`; U1-04: the 1–3 evals in each of the 24 scenario files). For each eval check:

1. Its `check "<name>" 'node --input-type=module -e "…"'` line becomes `test("<name>", () => { … })` in the module's
   test file, the eval's body translated: an `if (!cond) process.exit(1)` becomes `assert.ok(cond)` or the precise
   `assert.equal`/`assert.deepEqual`/`assert.match`; a `console.log` compared in bash becomes an assertion on the value.
   **Every behaviour the eval checked is asserted**; an eval that checked three branches becomes three assertions in one
   test (the name is one name). The bash line is deleted.
2. An eval that bash wrapped (a pipe into `grep`, a comparison against a file the check file made, `widest` in
   `tests/lib.sh`) stays a bash check where the bash part is the behaviour; where the bash was only plumbing around a
   pure call, it moves. The session lists each kept eval in the decision file with one line of why.
3. A check file left with no checks is deleted; one left with a few non-eval checks keeps them (its name stays; the
   `-pure-` files that keep bash checks are renamed in phase 4, not here).
4. The fixture is unchanged for moved names. A full run's conformance (`N/M checks passed`, `conformance: …` PASS) is
   the step that proves the move lost nothing; the feature's step says so and the session runs it.

**Checks (written first).** The moved tests themselves (test-first: the test file is written, run red against a
deliberately wrong assertion once, then green); `node --check` on every `tests/unit/*.test.mjs`; `bash -n` on every
check file touched; the full run's conformance green with the fixture's moved names untouched (`git diff
tests/fixtures/check-names.txt` shows only additions).

### U1-05 · The measurement

**Choice.** Before and after rows in `findings-and-research/2026-11-03-unit-tier.md`:

- *before*, in a scratch worktree of the run's base commit: `strace -f -e trace=execve -o <f> bash tests/run.sh
  <the eval files' names>` counting successful `node` execs, and `/usr/bin/time -v` user+sys of the same command; the
  same with `TEST_JOBS=1` for the wall of the pure files alone.
- *after*: the same over `bash tests/run.sh 00-unit` plus whatever eval files survived, and `node --test

  no other suite alive: `harness status` first; this run is one lane) before and after, as C1-04 did.

### U1-review

One review feature sized to the milestone (`decisions/2026-10-26-reviews-sized-to-milestone`): an Opus reader of the
diff; what to read hardest is every translated assertion against the eval it replaced (a weakened assertion is the
risk: `assert.ok(x)` where the eval compared a value), module-level state in any test file, and the reporter's handling
of a failure message with newlines.
