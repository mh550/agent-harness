# Status UX: read views that show what is running and what needs Michael, one needs-you record, cards with locations (2026-10-27)

**Goal.** Michael types `harness status` and sees, in one screen, what needs him, what is running, what is queued
and what finished recently, with a footer for the rest. Every read command (`status`, `queue list`, `needs` /
`parked`, `report`, `trends`, `gc --dry-run`, the new `show`) renders through one small formatter, so they look alike:
aligned columns, section headers and thin rules, a fixed glyph set with an ASCII fallback, colour on a TTY only,
widths that fit 80 and 60 columns without the terminal wrapping a field. Every path that stops for Michael writes
the same structured **needs record**, and each record carries a **card**: what is blocked and what waiting costs, why
(the system involved, in a few sentences), where (absolute paths with lines, commit, GitHub URL), the options with a
recommendation, and the exact commands. Five bugs seen this week are fixed on the way. Three milestones, U1 to U3,
each shippable alone.

**Source.** Michael's observations of 2026-10-27 (below, *What Michael saw*), the read-only output of this box on
2026-10-27 around 10:30 (*Before → after*), and the code as of `main` at `c721f66`. CLI conventions follow
[clig.dev](https://clig.dev/) and the way established tools handle defaults: `docker ps` shows running containers
only (`-a` for all) and truncates long fields; `gh run list` shows a bounded recent list with relative times and has
`--json <fields>` for scripts; `kubectl get` prints aligned columns, `-o wide|json`, and `-A` for every namespace;
`git status` groups by section and prints the next command as a hint; `systemctl list-units` shows active units by
default (`--all`), prints `●` and falls back to `*` off UTF-8, colours only on a TTY, and has `--plain` and
`--no-legend` for scripts. Colour follows [no-color.org](https://no-color.org/): any non-empty `NO_COLOR` turns it off.

**Rules.** `CLAUDE.md` binds: worktree only; never touch real runs or real state (this spec's checks build every run,
queue entry, state dir and needs record in `tests/lib.sh`'s throwaway environment); bash and node ≥ 20 stdlib only,
no npm packages; fakes mirror the live API (fixtures below are copied from real files and named with their source);
every behaviour visible in `harness-log.md` (`note`) and checked test-first in a `tests/checks/` file by topic, names
in `tests/fixtures/check-names.txt`; `bash -n` and `node --check` on every file touched; a decision file per behaviour
change; `docs/architecture.md` and `README.md` in the same milestone. **Proceed on the defaults in *Defaults for open
questions*; record them in the decision files; never park.**

**What is not changed.** `summary.json`'s existing keys and meanings (new keys only); `report.md`'s and `harness
trends`' markdown when stdout is not a TTY (byte for byte: the debrief, the ledger, n8n and the checks read it);
`harness parked --json`'s element keys; the notification titles the checks look for (`[<run>] <id> needs you`,
`[<run>] <m> needs you`, `[<run>] ended: <reason>`); the event JSON v1 contract in
`docs/specs/2026-10-22-n8n-events.md` (this spec fills its fields, adds none to the event); `gc`'s line texts
(`would:`, `+`, `!`, `keeps`) off a TTY; the queue runner's scheduling (U3 item 5 adds a warning and a record, never a
hold).

## The output contract (U1 builds it; every read command follows it)

**`lib/view.mjs`**, pure exported functions with unit checks, no dependencies. Every read view in node imports it;
bash views pipe tab-separated rows into `node lib/view.mjs table|card|section`.

| Rule | Value |
|---|---|
| Width | `COLUMNS` when it is a whole number ≥ 40; else the terminal's width when stdout is a TTY (`process.stdout.columns`); else 100. Lines never exceed it, except a URL (below). |
| Layouts | **normal** at ≥ 72 columns: one line per row. **narrow** below 72 (a phone over ssh, a Remote Control desk asked for `COLUMNS=60`): a row's essentials on its first line, the long field on an indented second line. |
| TTY | `process.stdout.isTTY`, overridden by `HARNESS_TTY=1` or `0` (the checks). |
| Colour | only when TTY, `NO_COLOR` unset or empty, `TERM` not `dumb`; `HARNESS_COLOR=always` or `never` overrides (the checks). Red ✗, yellow ⚠, green ✓, cyan ●, dim for secondary text. Colour never carries meaning alone: the glyph and the words say it too. |
| Glyphs | `●` running · `✓` done · `✗` failed · `■` stopped · `‖` paused · `⚠` needs you · `○` queued · `·` separator · `─` rule · `…` cut. ASCII: `*` `+` `x` `#` `=` `!` `o` `-` `-` `...`. Unicode when `LC_ALL`, else `LC_CTYPE`, else `LANG` names UTF-8 (case-insensitive); `HARNESS_GLYPHS=unicode` or `ascii` overrides. Every glyph is a single-column, text-presentation code point (a unit check lists them against a fixed set): no emoji, no `⏸` (rendered two columns wide by many terminals, hence `‖`). |
| Sections | `TITLE <count> · <hint> ───…` to the full width; a section with nothing in it is one line (`QUEUED 0 · runner off`), never omitted from `status`. A thin rule and a one-line footer end a view that hides anything, saying how to see it. |
| Columns | aligned; numbers right-aligned; one *flex* column takes what is left and is cut with `…`; ids (run ids, refs, feature ids) are never cut, so every command printed can be pasted. |
| Long text | a table cell is cut, never wrapped; a card value is word-wrapped with a hanging indent under its label; a cut field names the full view (`harness queue show 2`, `harness status <run>`). |
| URLs | never cut or wrapped by the formatter: on a line of their own, indented two spaces, allowed past the width. |
| Times | tables: relative, `now` `4m` `3h` `2d` `5w`; cards: `2026-10-27 00:19 (10h ago)`. `HARNESS_NOW=<epoch>` fixes "now" (the checks). |
| Paths | text views abbreviate `$HOME` to `~` (still a shell path); `--json` always absolute. |
| Money | tables: whole dollars (`$69`); cards and `--json`: cents (`$69.06`, `69.06`). |
| Machine output | `--json` where named: one JSON document, `"v": 1`, keys only ever added within v1 (a removal or rename is v2), no colour, no glyphs. A fixture lists every key path (`tests/fixtures/status-json-keys.txt`), and a check compares. |
| Streams | the view to stdout; errors to stderr with `harness: ` and a non-zero exit; no pager (a recorded default: the views are short by design; `--all` piped to `less -R` for the long one). |

API (each a pure function of its arguments): `context({env, isTTY, columns})` → `{width, narrow, tty, color,
glyphs}`; `glyph(name, ctx)`; `paint(text, style, ctx)`; `displayWidth(s)` (ANSI ignored; East Asian wide characters
count 2); `cut(s, n, ctx)`; `pad(s, n, align)`; `table(rows, columns, ctx)` (columns: `{key, min, max, align,
flex}`); `section(title, count, hint, ctx)`; `rule(ctx)`; `card(header, fields, ctx)` (label column 11 wide);
`ago(epoch, now)`; `when(epoch, now)`; `home(path)`; `duration("24h")` (`30m`, `6h`, `2d`, `1w`, or `YYYY-MM-DD`) →
seconds; `endClass(reason)` (below).

**End classes** (`endClass`, a unit check over every end reason the driver writes, copied into
`tests/fixtures/end-reasons.txt` from `finish` and the `ended` lines in this box's `harness status` of 2026-10-27,
sanitised): `done` → ✓; `stopped by Michael[: …]`, `session cap (…)`, `deadline`, `deadline (paused)`, `weekly
budget (…)`, `usage limit (… sessions refused in a row)`, `merge only` → ■; `blocked on …`, `waiting on Michael: …`
→ ⚠; `no feature left to try`, `feature-list edits`, `initializer failed`, `usage limit before the feature list`,
`unknown POLICY`, `driver exited unexpectedly (see run.log)` → ✗. An unknown reason is ✗, never a crash.

## U1 · The formatter, `harness status`, `harness queue list`

**Finding.** `cmd_status` (`bin/harness`) loops over every `$STATE_ROOT/*/*/` and prints a headline plus `${N:-3}`
lines of `run.log` per run, with no filter, no order but the glob's, and no record once a worktree is gone. `cmd_queue
list` prints raw arguments. The debrief (`lib/debrief.sh`: `N=3 harness status <run>`, `N=1 harness status <run> |
head -1`), the supervisor prompt (`N=20 harness status <run>`), the desk prompt, the `harness-answer` skill and
`prompts/project-catchup.md` read these views as text.

1. **`lib/view.mjs`** as the contract above, with its unit checks.
2. **`lib/status.mjs`** renders `status` from one line per run on stdin (as `parked.mjs` does): `<run>\t<project>\t
   <state dir>\t<worktree>\t<record dir>\t<alive 0|1|2>` (2: ending, the driver is in `finish`) plus the runner's
   pid state, the queue dir and the ledger dir as arguments. It reads, itself: `ended`, `PAUSE`, `LIMIT_UNTIL`,
   `port`, `tests-start`/`tests-end`, `run.log` (the newest `session <n> · <id> · <model>` line and the run's
   start), `metrics.jsonl` (cost, session count), the feature list, and for an ended run whose worktree is gone,
   `summary.json` from `$STATE` then the ledger copy (`<ledger>/<project>/<run>/summary.json`), so a gc'd run shows
   `23/23`, not `no feature list yet`. One node process for the whole view; `bash` collects only what node can't
   (alive pids, units when asked). Budget: under 1 s for 30 runs (a check times it on 30 stub state dirs).
3. **The default view**, four sections in this order, then the footer:
   - `NEEDS YOU <n> · harness needs`: in U1, derived (U2 replaces the source with the records): each parked feature
     (`parked.json`), each `needs-<m>` marker, each refused or conflicting merge (`refused-<m>`, `conflict-<m>`), and
     each run that ended `blocked on …` / `waiting on Michael: …` / an ✗ class. One row per item: glyph, run, a short
     headline, passing, cost, age of the item. Block items first, then oldest first. Never windowed: an item shows
     until it is resolved. A run whose worktree is gone has nothing left to answer and lists no item (as `harness
     parked` does today), so `voice-concierge-2026-10-19`'s 2026-10-20 crash doesn't sit there forever.
   - `RUNNING <n>`: every live driver, oldest start first: glyph (`●`, `‖` paused, `⚠` ending with a needs item),
     run, *what* (`<feature> · session <n> · <model alias>`; `waiting for the usage limit until 14:05`; `paused`;
     `2 lanes` with P2-06's sub-rows), passing, cost, age since the segment started.
   - `QUEUED <n> · runner going|off (harness queue start)`: the first three entries as `harness queue list` rows,
     then `+<k> more: harness queue list`.
   - `FINISHED · last <window> · <n>`: runs that ended inside the window, newest first; at least the 3 newest ended
     runs whatever their age, at most 10. Window: `--since`, else `STATUS_SINCE` from the user config (read-only
     source, as `queue list` does), default `24h`.
   - Footer: a thin rule and `<k> older runs: harness status --all · --since 3d · one run: harness status <run>`.
4. **Flags:** `--all` (`-a`: every run, newest first, sections kept); `--since <duration|date>`; `--project <name>`
   (`-p`, resolved as in U3 item 1; in U1 the directory name of the state dir); `-v` (each running run's units with
   `MemoryCurrent`, P2-06's lane lines, the last `N` log lines, `N` default 3); `--json`. The environment variable `N`
   still works and implies `-v`, so the supervisor's `N=20` and the debrief's `N=3` keep working.
5. **`harness status <run>`**: a card. First line `<glyph> <run> · <project> · <state or end class> · <x/y passing> ·
   <ago>` (since the start while running, since the end after; the debrief's `head -1` reads it), a rule, then
   labelled fields: `now` (running: feature, session, attempt of max, model, minutes in), `ended` (when and the full

6. **`harness status --json`** (v1): `{v, generated_at, since, runner: {up, max_parallel_runs}, needs: [...],

9. **Prompts and docs:** `prompts/supervisor.md` (`harness status {{RUN_ID}} -v`, `N=20` still works),

## Defaults for open questions (record each in its decision file)

1. **Window:** FINISHED shows the last `24h` (`STATUS_SINCE`), never fewer than the 3 newest ended runs, never more
   than 10. NEEDS YOU and RUNNING are never windowed.
2. **A run in NEEDS YOU and FINISHED** is listed in both: one row is an item, the other the run's outcome.
3. **Session number** in views is the run's count of sessions so far (`metrics.jsonl` rows, plus the one running;
   lanes P1's `$STATE/sessions` when it exists), not the per-segment counter in `run.log`.
4. **Narrow** below 72 columns; width from `COLUMNS`, else the TTY, else 100. No `--width` flag.
5. **Glyphs** `● ✓ ✗ ■ ‖ ⚠ ○`, ASCII `* + x # = ! o`; `‖` for paused instead of `⏸` (two columns in many
   terminals). Unicode whenever the locale is UTF-8, on a TTY or not.
6. **Colour** only on a TTY; `NO_COLOR` wins over everything but `HARNESS_COLOR=always`.
7. **No pager**, no interactive prompt in any read view.
8. **report/trends** keep their markdown off a TTY, so every reader of them today is untouched; the formatted form
   is for a person at a terminal (`--md` forces markdown).
9. **Needs record location** is the state dir (survives gc, no record lock); `needs.md` in the record is the phone's
   copy. `context` is null until the n8n events spec's A2 bundle exists; then that spec sets it.
10. **Needs kinds** stay inside the event v1 enum (`park`, `needs_michael`, `blocked`, `limit`); `reason` carries
    the detail, so n8n's routing (park, needs_michael, blocked) needs no change. Warn items have empty priority.
11. **Overlap** warns and records; it never holds a start. A live same-project run holds a plain start (queue); an
    ended run's unmerged branch does not.
12. **Paths** in text views abbreviate `$HOME` to `~`; at narrow width a path is cut at the front (`…/file:line`);
    URLs are never cut.
13. **Files fill** takes at most 8 paths, the entry's `files` first, then the session's diff, absolute.
14. **`harness needs done`** is the only write the read commands gain, and it writes only `$STATE/needs/`.
15. **The skill** `skills/harness-answer/SKILL.md` is edited in this repo only (its install is a symlink Michael
    made, `README.md`); nothing is written under `~/.claude`.
