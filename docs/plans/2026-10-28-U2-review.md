## Important

1. **The merge_conflict card recommended a fix that could not work.** Option (a) said to merge main into the lane
   branch by hand, push, and run `harness merge`. But `merge_one` merges the verified *tag*, so a hand merge never
   reached it. Worse, the once-per-main guard on `conflict-<m>` made `harness merge` return without a word while main
   stood still. **Fixed:**
   - Under `harness merge` (`HARNESS_MERGE_ONLY`) with an open `merge_conflict:<m>` record, `merge_one` fetches the
     lane branch. When its tip holds the verified commit, the tag moves there and the merge goes on from it (forced
     tag push, as `rebase` does). It notes `<m>: main merged into its branch by hand; re-tagged run/<run>/<m> at <sha>`.
   - The conflict guard no longer holds back `harness merge`, which says the conflict again, as it already did for a
     refused merge.

   Checks: *harness merge takes main merged into the lane branch by hand …* (it pastes the card's own commands, with
   the conflict resolved between them), *harness merge at the same main says the conflict again*.
2. **Pasteable commands ran in reused or live worktrees.** Before, they were `cd <slot> && git merge …`. The slot is
   `slot-<k>` and the next milestone takes it, perhaps mid-session. `main_conflict:record` pointed at the record
   worktree a live driver commits in. **Fixed:**
   - `onBranch` in lib/needs.mjs fetches, then adds a detached worktree of its own at origin's copy of the branch:
     `${HARNESS_SCRATCH_ROOT:-/tmp/harness}/<project>/fix-<run>-<subject>`, passed as `fix_root` by `needs_open`.
   - The fix runs there and the last command pushes `HEAD:<branch>`.
   - merge_conflict, main_conflict and verify_red start from the branch; base_conflict starts from main (the lane
     opens on origin's copy of its branch).

   Check: *a card's commands fix the branch in a worktree of its own …*. 59- and 61- read the new commands.
3. **`harness needs done` on a parked record did nothing visible.** The record moved to `done/`, then `list`
   synthesized `<run>/parked:<id>` from `parked.json`. **Fixed:** `done` refuses a parked record with the words of the
   synthesized one: it resolves when the feature is unparked (a new answer, then `harness continue`) or passes.
   Check: *harness needs done on a parked record is refused …*.
