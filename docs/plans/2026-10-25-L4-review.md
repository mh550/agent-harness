**The deletion question.** L4 made gc run unattended (the queue runner, every night, with `--all-merged --deps`) and
made its worktree removal forceful (`--force`, then `rm -rf`). Both turned guards that used to be git's (a plain
`worktree remove` refuses a dirty or locked tree) or Michael's (he ran gc by hand, when nothing of his was open) into
guards gc must hold itself. Three did not hold (#1 to #3). After the fixes:
- gc removes only a run's worktree (branch `harness/<run>`), clean by a status that sees untracked files whatever
  the config says, and `rm -rf`s it only once git has let go of it;
- `branch -d` still refuses anything unmerged locally; the remote pass deletes only branches that are ancestors of
  `origin/main`, never `main`, the origin's default branch or a running run's branch;
- `--deps` follows no symlink and no path out of the tree (the reviewer confirmed `..`, `.`, a leading `/` and a
  symlinked middle component all fail the realpath prefix test), touches nothing git tracks, and a live, queued or
  desk-open run keeps its deps.

The reviewer also confirmed: `--dry-run` deletes nothing in either pass; `alive "$d" || compgen … && continue`
groups as intended; `rm -rf`, `du` and `git ls-files` all take `--`; `PIPESTATUS` in `lib/queue.sh` is right and the
runner has no `set -e`, so a failed gc can't stop the debrief; `-d` refuses a branch checked out in a worktree.
