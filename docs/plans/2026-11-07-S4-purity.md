## The rules every build feature keeps

**1. Nothing a reader sees changes.** Every `check:` line, marker byte, flake row, note, card, exit reason, end reason,
queue file byte and runner log line stays as it is. The existing checks are the proof, so none of their assertions
changes. The fixtures gain only the new unit names (each in `tests/fixtures/check-names.txt` and
`check-names-fast.txt`, both `LC_ALL=C` sorted). `SERVED` in `tests/unit/cli.test.mjs` gains a script that
`lib/helper.mjs` gains: that list is the test's data, not an assertion.

**2. The note rule.** Every `note "…"` literal stays in its bash file. A pure function answers a branch and its values,
never a note's words. Both proofs of the by-hand plan must hold, with `<base>` = `git merge-base HEAD origin/main`:

```bash
git diff <base> HEAD -- lib/*.sh bin/harness | grep '^[-+].*note "'     # only pairs identical in their quoted text
d=$(git diff <base> HEAD -- lib/*.sh bin/harness)
diff <(sed -n 's/^-\(.*[^-a-z]\)\{0,1\}\(note ".*\)$/\2/p' <<< "$d" | sort) \
     <(sed -n 's/^+\(.*[^-a-z]\)\{0,1\}\(note ".*\)$/\2/p' <<< "$d" | sort)   # prints nothing
```

The second proof compares from `note "` **to the end of the line**, so a line that holds a note keeps everything after
`note "` byte for byte, its trailing code and comment included. That decides some shapes below. The three end-block
lines keep their `ends+=(…); fi`, for example, so `lib/lane.mjs` answers the lists and bash still builds the reason.
Run both proofs before ending a build session.

**3. Reaching the function.** `lib/record.sh`, `lib/lane.sh` and `lib/driver.sh` call through `ask` (`lib/record.sh`),
which the resident helper answers without a node start; `lib/lane.mjs` joins `SERVED` in `lib/helper.mjs`.
`lib/check.sh`, `bin/harness` and `lib/queue.sh` run outside a driver's or lane's shell and have no helper, so they
spawn `node` once per question. A subset `check.sh <args…>` call that ends normally spawns nothing new; one killed by
its timeout asks `why` once (the only way it can say so today). An answer with a newline inside a value (a queue
argument) is NUL-separated and comes from a spawn, because the helper declines a NUL. Every other answer is labelled
lines, `<label> <value>`, read by `while read -r k v; do case $k in …`.

**4. Bash's reads, mirrored exactly.** The trap in each move is a detail of the shell that the function must copy, with
a unit test:
- `read -r x` trims leading and trailing spaces, tabs and newlines (never `.trim()`, which takes more).
- `read` fails at end of file when the last line has no newline, even though it set its variables.
- `[[:space:]]` is not `\s`, which also takes a no-break space.
- `[[:alnum:]]` takes letters beyond ASCII in the driver's UTF-8 locale.
- `${w:0:200}` counts characters, not UTF-16 units.

**5. The Gotcha shapes.** A `| head` or `(( $(jq …) ))` in a function a move touches is rewritten to the safe shape
named in `CLAUDE.md`. On the base tree the touched functions hold these: `control` and `stop_why` (`| head -1`, gone
with the move), `entry_project` and `entry_overlaps` (`compgen … | head -1`: `mapfile -t m < <(compgen …); d=${m[0]:-}`,
or gone with the move). None of the touched functions holds `(( $(jq …) ))` any more.

**6. Each move's row.** A build feature fills its row of the decision file's Choice table: function, bash lines removed
(`git diff --numstat <base> HEAD -- <file>`), tests added, how bash calls it.

## S4-04 · the two parsers written twice → `lib/queue.mjs` (new), `lib/inbox.mjs`

**Empties.** The queue format: `queue_add` and `entry_overlaps` in `bin/harness`; `entry_project` and the start line

**`lib/queue.mjs`:**

| Function | Inputs | Answer |
|---|---|---|
| `encodeEntry` | the arguments | the file's text, one per line, each newline as `\x1f` |
| `decodeEntry` | the file's text | the arguments: a newline at the end dropped, a CR at each line's end dropped, `\x1f` back to a newline; an empty file is `[]` |

The CLI spawns once per question: `add <queue dir> <verb> <arg>…` (prints the path, what `queue_add` prints), `decode
<file>` (NUL-separated), `projects <state root> <file>…` (`<file>\t<project>` per line, one spawn per poll with entries,

*Two details to hold.* `argsOf` drops a CR and `mapfile -t` doesn't: the one decoder drops it, *default*, as `argsOf`'s
comment explains (a file edited elsewhere). The only change is that a hand-edited CRLF entry starts with clean
