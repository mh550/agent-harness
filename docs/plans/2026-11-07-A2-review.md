## The hard questions

1. **Does `context_runs` emit the bytes lib/debrief.sh emitted before the move?** Not quite, before this review. The
   reviewer compared old and new byte for byte: it ran the base commit's lib/debrief.sh and the moved one with
   `--dry-run` on `status_stubs 2` (9 runs). The bodies were identical apart from two places:
   - `ended`: A2-04 made it read the `ended` file before `alive` (I2).
   - `spend`'s jq literal (M3).
   Both are now fixed. The dry-run diff check (`context-bundle.sh`, "--since matches the debrief's dry-run context but
   the glossary") compares the two callers of the same function, so it cannot catch a regression in the move itself.
   The new check "the debrief's context says a finishing run is still running, as before the move" pins the old
   bytes where they differed.
2. **Does lib/glossary.mjs list an ID it cannot resolve under `unresolved`, and never pick a near match?** Yes,
   with one exception, now fixed: dotted ids (M2). Every resolution is an exact `===` comparison
   (`n.token === id`, `x.id === id`, `x.milestone === id`) with no case folding, prefix or substring test. `D2`
   never matches `D24`, `D-H1` never matches `D-H12`, and `Q99` stays unresolved.
3. **Can a failing or slow bundle block or fail a notification?** It cannot fail one: `notify` always returns 0.
   The bundle runs in a child process under `timeout 60`, with `</dev/null 2>/dev/null 8>&- 9>&-`, so it inherits no
   lock. A non-zero exit, a timeout, a missing context.json, a missing uuid, or `HARNESS_CONTEXT=false` each cost
   the note and `context: null`, and the POST or the ntfy fallback still runs (event-run's "a bundle that fails
   sends the event with a null context, noted"). A missing worktree or ledger copy is handled: `rec_dir` falls back
   to the ledger, the docs root to `PROJECT_DIR`, and context.mjs's reads are in `try`. A slow bundle can delay the
   notification by at most 60 s (M6).
4. **Does `harness context` write anything outside its out directory?** It did: `harness queue list` created
   `queue/done` (M4), now fixed. Its scratch `<out>/.work.*` is removed by the EXIT trap, also on timeout's TERM.
   context.json goes to a temp file first and is then renamed into place. The retention is safe: it runs only when
   the out directory's resolved parent is the resolved `<STATE_ROOT>/events`, it removes direct subdirectories
   only, and it skips the kept id, dot-names and symlinks.

## Simplifications

- Applied: one `ended_of` helper replaces the three `ended` expressions (run_context, context_glossary, and the
  ended-first variant). debrief.sh's page keeps its own alive-first test, which reads the same way.
- Applied: the debrief's second gather is gone (I1).
- Not applied: `resolveIds`'s `seen` set. findIds already makes the ids unique, but `resolveIds` is exported, and
  the set keeps a caller's duplicate ids from duplicating entries.
- Not applied: reusing run_context's `needs --all --json` in context_glossary (one `harness needs` per run saved).
  The two calls ask different questions (all items vs the open ones by row), and the cost is about 0.1 s.
