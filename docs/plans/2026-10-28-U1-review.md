# U1 review: the read views (`lib/view.mjs`, `lib/status.mjs`, `harness status`, `harness queue list|show`)

*(2026-10-28, run agent-harness-2026-10-28, feature U1-07.)* One Opus round read
`git diff origin/main...HEAD -- lib bin tests prompts templates docs/architecture.md README.md` (1,978 lines) from
`/tmp/harness/agent-harness/agent-harness-2026-10-28/U1-review.diff`. It found 1 Critical, so a second Opus round read the
fixes (`U1-review-2.diff`, 327 lines) and found 2 Important and 3 Minor issues in them (*Round 2* below). Every finding was checked against the code before it was fixed. Each fix has a check in
`tests/checks/56-status-review.sh` that failed before the fix and passes after it.

## Critical

1. **The session number counted every metrics row** (`runObject`). That included init, verify, retro and
   limit-refused rows, plus one more even after the newest session's row was written. A running run read
   `B · session 4` where the log said 2, and the card's `min in` counted from a session that had ended.
   **Fixed:** `coding(x)` counts the coding rows the lane kept (`kind: coding`, not `env`). `liveSessions(x)` adds
   the sessions still running (see round 2). The card's `min in` counts from the newest of them, and shows nothing
   when none is running. `status_stubs`' `mx` now writes init and limit-refused rows beside the
   coding ones, at `MX_AT` seconds before `HARNESS_NOW` (fakes mirror the live rows).
   Checks: *session counts coding sessions only …*, *between sessions … no minutes in*.

## Important

2. **A feature list without milestones printed `milestones undefined 1/2`** in the card. **Fixed:** `features(x)`
   puts a feature with no milestone in `default`, as `features.mjs`'s `laneOf` does.
   Check: *a feature list without milestones shows its features under default*.

## Minor

3. **One queue entry with an out-of-range `--until-epoch` crashed `harness status`, `queue list` and `queue show`**
   (`RangeError` in `iso`). **Fixed:** `iso` gives null for an invalid date; `show` prints the value as given.
   Check: *a queue entry with an out-of-range --until-epoch …*.
4. **An entry the runner took between the listing and the read printed a junk row** (`NaNw`, an empty verb).
   **Fixed:** `readQueue` drops an entry with no mtime. No check: it is a race, and a check would be timing-bound.
5. **Wall hours of a running, continued run include the days between segments.** *Not fixed* (below).
6. **`queue show` left the home directory whole in `spec` and `brief`.** **Fixed:** both go through the tilde rule.
   Check: *queue show shortens the home directory in spec and brief*.
7. **The card's `branch` line reads `origin/main`**, so a project with another `MAIN_BRANCH` shows no ahead or behind.
   *Not fixed* (below).
8. **Lane liveness is `kill -0` alone**, where `lane_live` in bin/harness also checks the pid's cmdline names
   `lib/lane.sh`. *Not fixed* (below).
9. **The footer's `--since 3d` hint shows whenever the window is under 3 days**, even when no hidden run ended in
   the last 3 days. *Not fixed* (below).
10. **`harness queue show --parked 2` died with the usage line**, and **a lane's `now` text reached the line
    unclean.** **Fixed:** `--parked` before or after the number, and `laneLine` cleans `now`.
    Checks: *harness queue show takes --parked before or after the number*, *a lane now line loses its control bytes*.

- `secs()` in place of the inline `Date.parse(t) / 1000`s.
- `SHOWN` is built from `VALUED` and declared before `entryArgs` uses it.
- RUNNING's id fold lost a condition that was never true.
- `widest()` moved from 53-, 54- and 55- into `tests/lib.sh`.
- Kept: `view.mjs`'s stdin CLI (`table|card|section`). The decision names it as the bash views' way in, and
  `51-view-pure.sh` checks it.

## Round 2 (the fixes)

1. **Important: a limit-refused session still counted as live.** Its row is `env`, so it never closed its `session`
   line, and the card's minutes kept growing through the wait.
2. **Important: with two lanes, one lane's row hid the other lane's live session.** The test only looked at the
   newest `session` line, and any lane's row closed it.
3. **Minor: a row written in the same second as the next `session` line hid that session.** `stamp()` is whole
   seconds.

   **Fixed (all three):** `liveSessions(x)` reads the segment's log in order. A `session <n> · <id> · <model>` line
   opens a session for `<id>`; lane.sh's `<id> · <model> · passes=…` note or `session for <id> hit a limit` note
   closes it. The run's `feature` and `model` come from the newest session still open, else the newest line.
   `status_stubs`' running run now has those lines, as lane.sh writes them. Checks: *between sessions …*,
   *a session waiting out a limit …*, *two lanes: one lane closing its session leaves the other live …*.
4. **Minor: the view's lane sub-rows (two lanes, no `-v`) printed `now` unclean.** **Fixed:** cleaned as in
   `laneLine`. The check *a lane now line loses its control bytes …* covers both.
5. **Minor: the `--parked` check piped into `head -1` under pipefail.** **Fixed:** it reads files.

Checked and fine in round 2: the other fixes and the simplifications change no output. All 7 first-round checks fail
against HEAD's code. Rewriting the rows' `at` in `mx` touches only the files that use `status_stubs`. Noted: after a
`harness continue`, `session` counts the whole run, so it can read `session 5` beside the log's `session 2`. The
decision says so.
