## What by hand means here

One interactive `claude` session per milestone, Michael at the terminal, M1 then M2 then M3. A session builds its
milestone's open features in the feature list's order from the spec, and takes the place of the run's parts:

| the run's part | by hand |
|---|---|
| a fresh session per feature | one session per milestone, one commit per feature |
| a feature's `passes` on a fast green | `bash tests/run.sh --tier fast` after the milestone's last feature, plus the slow files the change touches |
| the review feature (M1-04, M2-04, M3-04) | one read-only subagent with a clean context on the milestone's diff, the model the feature list names |
| verify (a fresh tree, the full suite) | `bash tests/run.sh` once, last, on the final tree, nothing edited after it |
| the milestone's PR, merged by the run | a PR titled `F1 M<n> by hand: …`, merged by the session |
| `entry.json`, the record, the retro | the PR's body: per feature what was built, verified how, discoveries, defaults against the spec, proposed changes |
| the supervisor's read of the run | the supervisor's read of the PR, the decision file and `main` |

What it gives up, on purpose and for F1 only: the independent verify session, the run's metrics rows and its retro.
What it keeps: checks first and watched failing, fakes that copy real lines, a clean-context reviewer, a full green
suite before every merge, one decision file per milestone, docs in the same milestone.

Suite time, the reason for the split (estimates from the run's numbers: full 816–870 s, fast ~150 s): the run would
have paid about 12 sessions × 17 min + 3 verifies × 14 min ≈ 4 h of suite (M1-01 ran the full suite in its session);
by hand it is 3 full runs + 3 fast runs + subsets ≈ 1 h.

## Rules for the three sessions (the prompt carries them)

- A session starts only when the milestone before it is on `origin/main` and `harness status` shows RUNNING 0.
- One suite at a time on this box; `TEST_JOBS` untouched; the full suite once per milestone, in the background with
  a timeout of 30 min, never polled.
- A session stops and asks Michael at these points only: before it starts building (its plan in five lines); a spec
  default it would contradict; a step it cannot build as written; a red outside its change it cannot explain; a
  second red full suite; anything a deny blocks. Everything else it does and reports.
- Subagents read and review; they never build. No `claude -p` from bash
  (`findings-and-research/2026-11-04-orchestration-models.md`, recommendation 4).
- `CLAUDE.md`'s `## Gotchas` holds 14 lines of memlint's 15 (M1-01 went red on a 15th counted with the comment): a
  new fact replaces a line or goes in the PR body.
