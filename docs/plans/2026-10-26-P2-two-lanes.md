### 2.2 The admission test

A new function in `lib/driver.sh`, beside `lane_open`:

```bash
# <lanes alive> → 0 (open), or 1 with "<kind>\t<reason>" (kind: memory, five-hour). The first lane always opens: its
# own mem_gate and limit_wait handle a short box (a refusal at 0 open lanes could stall the run for good).
admit() {
  local a=$1 gb need u r pct; (( a == 0 )) && return 0
  if gb=$(mem_available_gb); then need=$(( MEM_MIN_AVAILABLE_GB + LANE_RESERVE_GB * a ))
    (( gb >= need )) || { printf 'memory\t%s GB available, under %s GB (MEM_MIN_AVAILABLE_GB %s + LANE_RESERVE_GB %s x %s open)\n' \
      "$gb" "$need" "$MEM_MIN_AVAILABLE_GB" "$LANE_RESERVE_GB" "$a"; return 1; }
  fi
  if read -r u r 2> /dev/null < "$USAGE5" && [[ $r =~ ^[0-9]+$ ]] && (( r > $(date +%s) )); then   # a window not reset yet
    pct=$(awk -v u="$u" 'BEGIN { printf "%d", u * 100 + 0.5 }')
    (( pct < LANE_OPEN_BELOW_5H )) || { printf 'five-hour\t5-hour window at %s%%, opens under %s%% (resets %s)\n' \
      "$pct" "$LANE_OPEN_BELOW_5H" "$(date -d "@$r" +%H:%M)"; return 1; }
  fi
}
```

`mem_available_gb` is `scope.sh:91`'s reader (`HARNESS_MEMINFO` in tests; floored whole GB; no `MemAvailable` line
→ the memory test is skipped, as `mem_gate` does). `LANE_OPEN_BELOW_5H` is a percent; `USAGE_5H` holds 0..1.

The open loop (`driver.sh:443-449`) becomes:

```bash
while IFS=$'\t' read -r m kind; do   # kind: "rebase" from rebase_due (§3.1); F lanes' second field is its base tags
```

### 2.3 Ports

Slot 0's lane keeps the run's port (`$STATE/port`): one lane is today's run exactly, and P1's checks keep their
`lane M1 opened (slot 0, port 7950, …` text. A lane in slot `k ≥ 1` gets the first free port from `BASE_PORT`:

```bash
# lib/config.sh (bin/harness's port_taken moves here: cmd_start and the coordinator use one rule). Taken: something
# listens on it, a run holds it ($STATE_ROOT/*/*/port), or a lane holds it (lanes/<m>/port beside a pid, an svc-up or
# an opening file: a closed lane's port is free once its services are down)
port_taken() { local f d; (echo > "/dev/tcp/127.0.0.1/$1") 2> /dev/null && return 0
  grep -qsx "$1" "$STATE_ROOT"/*/*/port && return 0
  for f in "$STATE_ROOT"/*/*/lanes/*/port; do d=${f%/port}
    [[ -f $d/pid || -f $d/svc-up || -f $d/opening ]] && grep -qsx "$1" "$f" && return 0; done
  return 1; }
# lib/driver.sh: <m> → the port, written to lanes/<m>/port with lanes/<m>/opening (held from the allocation until
# lane_open has written the pid, which removes opening), under the record lock and the box-wide port lock
port_alloc_() { local p=$BASE_PORT; { flock 7; while port_taken "$p"; do p=$(( p + 1 )); done
  echo "$p" > "$STATE/lanes/$1/port"; : > "$STATE/lanes/$1/opening"; } 7> "$STATE_ROOT/port.lock"; echo "$p"; }
```

`lane_open` (`driver.sh:107-125`): after the slot is chosen and its leftover services stopped, `LANE_PORT=$PORT` for
`k == 0`, else `LANE_PORT=$(record port_alloc_ "$m")`; `slot_open`'s note and `lane.sh` then use `LANE_PORT` (today
both read `$PORT`, `driver.sh:121-123`, `record.sh:513`). A slot that fails to open removes `opening`. The record lock is the step's; it serializes one run's coordinator only,
so `$STATE_ROOT/port.lock` is what keeps two runs from taking one port: `cmd_start`'s loop (`bin/harness:225`, no lock
today) takes it too, from its search until `$STATE/port` is written. `prompt_vars` already renders a lane's port: `lane.sh:33` sets `PORT=$LANE_PORT`, and
`lib/prompt.sh:100` reads `lanes/<m>/port` in command mode (discovery P1-04: no new per-lane value, so no new line there).

### 2.4 The merge lock, the run's end, the counter

- **Merge lock.** `merge_milestones` runs its loop under `flock 8` on `$STATE/merge.lock` (`{ flock 8; …; } 8>
  "$STATE/merge.lock"`), in the lane and in the coordinator alike; the second caller then finds `merged-<m>` and skips
  it. Lock order is merge → record (`merge_one` calls `note`, `rec_commit`, `sync_record`); nothing under the record
  lock calls `merge_milestones`. The network commands inside (`git fetch`, `git push`, `$GH`, and `sync_record_`'s
  fetch and push and `notify`'s post, which run under it through `merge_one`) get `8>&-`, as `sync_record_` closes 9. The re-base work (§3) runs **outside** this lock.
- **The run's end reaches every lane.** When `reap` sets `LANE_END` (`driver.sh:99`), it also writes
  `$STATE/lanes-end` with the reason (the driver's start removes it beside `lanes/*/pid`). A lane checks it first
  at the top of its loop (`lane.sh:145`, before the cap) and exits **16** with `16 the run is ending (<why>)`; `reap` treats
  16 as a plain close (no `LANE_END`, no `needs-<m>`). `limit_wait` (`record.sh:161-173`, one `sleep "$w"` today) and
  `mem_gate`'s wait sleep in slices of at most 60 s and return early when `$STATE/lanes-end` exists or `control` says
  `stop`, so `finish`'s `wait_lanes` never waits out a five-hour window. The lane exit table (`lane.sh:4-7`, the P1
  plan §1) gains row 16.
- **`rec_count`.** `rec_count_` prints the new value inside the lock and `rec_count` returns that output
  (`rec_count() { record rec_count_ "$1" "${2:-0}"; }`), so two lanes never get one session number. The cap becomes
  atomic: `n=$(rec_count "$STATE/sessions" 1); (( n > MAX_SESSIONS )) && { rec_count "$STATE/sessions" -1 > /dev/null;
  lane_exit 13 "session cap ($MAX_SESSIONS)"; }` at `lane.sh:208`; the cheap check at `lane.sh:145` stays.

### 2.5 The brief's runner timeout (placed in P2-02: a hung two-lane check must not cost a 15-minute suite)

Not `timeout` around the file: GNU `timeout` puts the file in a process group of its own (a Ctrl-C or check.sh's
stop would no longer reach it) and becomes the file's parent (`33`'s `rk` file, `kill -9 $PPID`, would then read as a
timeout, not "ended without its exit status"). Instead `one()` runs `setsid bash "$1"` (the file leads its own group,
its parent is still `one`'s subshell) with a watchdog beside it: after `${TEST_FILE_TIMEOUT:-10m}` it writes
`$out/<file>.timedout` and sends `TERM` to the file's group, `KILL` 10 s later. `stopped()` (the runner's TERM/INT/HUP)
now also sends `TERM` to each running file's group, so a stop still reaches every file. `replay` prints a timed-out
file's output so far and one line, P0-04's shape, `FAIL <file>: still running after TEST_FILE_TIMEOUT=<t>; stopped`
(counted like `no_fail`'s line, so the total can't read all passed). `tests/lib.sh` traps `TERM` to `exit 143`, so a
file's EXIT trap (`rm -rf $T`, its private tmux server) runs before the `KILL`. Drivers a file started in tmux are
outside its group either way; that trap's `tmux kill-server` ends them.

## 3. The re-base rule (P2-03)

### 3.1 Where it is found

`merge_one` (`record.sh:358-400`) today notes `<m> verified, but main moved since; not merged (needs Michael)` when
`git merge-tree --write-tree origin/main <tag>` differs from the tag's tree (D1 of the P1 plan). P2: that branch
returns **3** (`main moved`) with no note and no `needs-<m>`; the `--open` call (a dependency not merged yet) skips the
test altogether, since main moves again when the dependency lands and the rule runs then. `merge_milestones`, on 3,
writes `$STATE/rebase-<m>` (the main sha) and goes on to the next milestone. Called outside a lane (the coordinator,
`finish`), it skips a milestone whose lane is alive: that lane merges its own, and a `reap` during its re-base would
otherwise find the old tag and ask for a second re-base.

Who does the work, so it always runs in a slot, in the lane's check scope, outside the merge lock:

- **In the lane** (`verify`'s `hold` branch, `lane.sh:100`): `merge_milestones "$m"`, then
  `while [[ -f $STATE/rebase-$m ]]; do rebase "$m" || break; merge_milestones "$m"; done`.
- **In the coordinator** (`reap`, `finish`, start-up): a `rebase-<m>` with no lane alive for `<m>` is a candidate:
  `rebase_due` prints `<m>` for each, in list order, ahead of `F lanes`' lines, through the same admission and slot
  count. `lane_open` starts it with `LANE_MERGE=1`; `slot_open` then checks out the tag
  (`git checkout -B harness-lane/<run>/<m> run/<run>/<m>`, the verified commit, whatever the branch holds), and
  `lane.sh` runs only `rebase`, the merge loop above and `lane_done`.
- **In `finish`** (lanes all exited): a `rebase-<m>` left is noted once, `<m> verified, but main moved since; harness
  merge <run> re-bases and merges it`, and kept for the next segment or `harness merge`.
- **`harness merge <run>`** (`HARNESS_MERGE_ONLY`, `driver.sh:318-325`): after `merge_milestones`, until no new
  `rebase-<m>` appears (a dependent's appears only once its dependency merged): for each in list order, `lane_open
  "$m"` with `LANE_MERGE=1` (and `HARNESS_MERGE_ONLY` passed on), `wait_lanes`, `merge_milestones`; then `slot_close`.
  This path exits before `driver.sh:405` exports what `lane.sh` reads under `set -u` (`lane.sh:14`, `:29`, `:40`),
  so it exports `HARNESS_T0=$T0 HARNESS_DEADLINE=$DEADLINE LANE_MAX_SESSIONS=$(( 3 * features + 5 ))` itself (a merge
  lane runs no coding session) and `mkdir -p "$STATE/lanes"`. Under `pr` this is "opens a slot from the tag and runs
  the same rule".

### 3.2 `rebase <m>` as git commands (lib/lane.sh; cwd the slot, on `harness-lane/<run>/<m>`)

```bash
tag=run/$RUN_ID/$m; c=$(git rev-list -n1 "$tag"); rm -f "$STATE/rebase-$m"
git fetch -q origin "$MAIN_BRANCH" 8>&-; mn=$(git rev-parse "origin/$MAIN_BRANCH")
[[ -f $STATE/merged-$m ]] || git merge-base --is-ancestor "$c" "$mn" && return 0   # merged meanwhile: nothing to re-base
                                                        #   (else an empty `ours` would read as disjoint and re-tag main's tip)
base=$(git merge-base "$c" "$mn")                       # main as this lane last merged it (verify's sync_main)
git checkout -q -B "$LBRANCH" "$c"                      # the verified tip, nothing else
git merge -q --no-edit "origin/$MAIN_BRANCH"            # conflict: git merge --abort; git reset -q --hard "$c";
                                                        #   note "<m> conflicts with main; not merged (needs Michael)"; needs-<m>; return 1
theirs=$(git diff --name-only "$tag..HEAD")             # what main brought in
ours=$(git diff --name-only "$base..$tag")              # the milestone's own (and its unmerged dependencies')
both=$(comm -12 <(sort <<< "$ours") <(sort <<< "$theirs") | paste -sd' ')
n=$(grep -c . <<< "$theirs")
```

**Disjoint** (`both` empty) and `LANE_REBASE=suite`:

```bash
run_init fresh                                          # the install, then the suite in full (marker cleared) in
                                                        #   harness-<run>-<m>-check-<pid> (HARNESS_SCOPE_PREFIX, lane.sh:42)
cp "$SCRATCH/init.out" "$LDIR/rebase-check.out"         # its `check: green (…)` line, uncached: the check's evidence
green || { …red path below… }                           # the verdict: the marker run_init's suite just wrote
git tag -f -a "$tag" -m "harness run $RUN_ID: $m verified (v3); re-based on $MAIN_BRANCH ${mn:0:7}, suite green"
git push -q --force origin "refs/tags/$tag" 8>&-        # the only forced ref: the old commit stays reachable from the PR head
sync_lane                                               # the lane branch: a fast-forward to the merge commit
note "$m re-based on $MAIN_BRANCH ${mn:0:7}: $n files, disjoint, suite green; re-tagged"
rec_commit "HARNESS: $m re-based"; sync_record
```

The tag's subject keeps `(v3` so `merge_milestones`' v2 test (`record.sh:415`) still passes it. `merge_one` then
pushes `harness-merge/<run>-<m>` at the new commit (its existing `-f` push, a fast-forward here) and merges with
`--match-head-commit` the new commit. A red suite: `git reset -q --hard "$c"` (the merge commit is never pushed),
`note "$m re-based on $MAIN_BRANCH ${mn:0:7}: $n files, disjoint, suite red; not merged (needs Michael)"`, `needs-<m>`,
`needs_you`, return 1.

**Overlapping** (`both` not empty), or `LANE_REBASE=verify` in every case: `r=$(( $(cat "$STATE/rebase-rounds-$m" 2>
/dev/null || echo 0) + 1 ))`. Over `MAX_REBASE_ROUNDS`: `git reset -q --hard "$c"`, `note "$m re-based on …: $n files,
overlapping ($both); its $MAX_REBASE_ROUNDS re-base round(s) used; not merged (needs Michael)"`, `needs-<m>`, return 1.
Else `echo "$r" > "$STATE/rebase-rounds-$m"`, `sync_lane` (the verify works on the merged commit), `note "$m re-based
on $MAIN_BRANCH ${mn:0:7}: $n files, overlapping ($both); one verify round ($r of $MAX_REBASE_ROUNDS)"` (with
`LANE_REBASE=verify` the parenthesis reads `LANE_REBASE=verify`), then `verify "$m" rebase`.

`verify`'s new `rebase` mode, like `once`: no attempt is granted on a failure (`maxr=$rounds`), the escalation to
`VERIFY_ESCALATE_MODEL` stays, the clock says `re-base verify round <r> of <MAX_REBASE_ROUNDS>`; on `hold` it tags with
`git tag -f -a` and pushes `--force origin refs/tags/$tag` (plain `git tag -a` fails silently on an existing tag,
`lane.sh:96`). Every other path is today's verify.

A main that moves again during a re-base is found by the next `merge_one` and runs the rule again; suite re-bases are
capped at 3 per lane process, then `note "<m>: main moved during 3 re-bases; not merged (needs Michael)"` (D3).

P1 Minor 7 goes here: `verify` removes `nomerge-<m>` at its start (`lane.sh:53`), so a clean later verify merges.

### 3.3 The invariant

After a re-based merge, `git -C "$T/origin.git" diff --quiet run/<run>/<m> main` holds (the tag's tree equals main's
right after its PR; the stub's `pr merge` is a `--no-ff` merge of the tag commit, whose tree already contains main).
The checks set `RECORD_PR=off` (the suite's base config does, §5.3), so no record PR moves main after the last lane.

## 4. Slots, branches and gc (P2-04)

- **Slot reuse** is P1's; the check proves the ignored directory survives (§7).
- **A merged lane's branch** goes when its PR merges, not only at `finish`: `merge_one`'s success branch
  (`record.sh:385-387`) runs `lane_branch_gone <m>`: `git push -q origin --delete harness-lane/<run>/<m>`; locally `git
  branch -D` when no live lane has it checked out (a slot whose lane closed is first `git -C <slot> checkout -q
  --detach`; the lane merging itself leaves it to `reap`, which calls `lane_branch_gone` for a lane closing
  `<m> merged`). Each deletion is a note, `lane <m>: branch harness-lane/<run>/<m> deleted (merged)` (P1 Minor 11);
  `slot_close` and `lanes_term` note theirs too. Under `pr` the slot is freed at verify (the lane exits `0 <m>
  proposed`) and the branch stays until `gc` sees it merged.
- **`cmd_gc`** (`bin/harness:433-554`):
  - The branch passes: `prefixes=(harness/ harness-merge/ harness-lane/)` (`--all-merged`'s bare prefix covers it
    already). `running()` learns lane branches: `r=${1#harness/}; r=${r#harness-lane/}; r=${r%%/*}`, so a live run's
    lane branches are never candidates.
  - The worktree pass: a worktree under `$WT_ROOT/<project>/lanes/<run>/slot-<k>` is a slot. It is removed (the
    same `worktree remove --force`, prune, `rm -rf` steps) when its run's state dir `$STATE_ROOT/<project>/<run>`
    has no live driver (`alive`), no live lane (`$d/lanes/*/pid` naming a live process: a SIGKILLed driver's lane
    lives on), no queued continuation (`running "harness/<run>"`), no open desk, and the slot is clean, **whatever
    its branch's merge state** (the branch keeps the work; `harness continue` makes the slot again). Kept slots say
    why: `keeps <slot>: lane <m>'s process <pid> is alive` / `…: uncommitted work`. Then `rmdir lanes/<run>` and
    `lanes/` when empty. Slots are recognised by path **before** the pass's `[[ -n $b … ]]` test
    (`bin/harness:485`): a closed lane's slot is detached (below), and a detached worktree would be skipped there.
  - `--deps`: the deps loop's match (`[[ -f $d/ended && meta WT == wt ]]`) also takes a slot of an ended run with no
    live driver or lane (a kept, dirty slot still frees its `DEPS_DIRS`).
  - The unit pass (`bin/harness:442-458`) matches lane units already (`scope_owns`); it learns one thing: a run with a
    live lane process (a SIGKILLed driver's lane lives on) is busy like a live driver, so its session scope is left.
- **P1 Minor 8** (`lanes_orphans` matching the pid by command line only): it also requires `STATE=$STATE` in
  `/proc/<pid>/environ`, so another run's lane on a recycled pid is never signalled.

## 5. The record PR (P2-05)

### 5.1 `record_pr` (lib/driver.sh), the last step of `finish`

After the ledger, `scratch_done` and the continuation's commit (`driver.sh:260-273`), before the final `log`:

```bash
record_pr() {
  [[ $RECORD_PR == off ]] && { note "record PR: none (RECORD_PR=off)"; return 0; }
  [[ $MERGE_POLICY == off ]] && { note "record PR: none (MERGE_POLICY=off)"; return 0; }
  local url head; sync_record; head=$(git -C "$RWT" rev-parse HEAD)
  url=$($GH pr view "$RBRANCH" --json url,state -q 'select(.state=="OPEN") | .url' 2> /dev/null) || url=""
  [[ $url == http* ]] || url=$($GH pr create --base "$MAIN_BRANCH" --head "$RBRANCH" --title "$RUN_ID: run record" \
    --body-file "$REC/report.md" 2>> "$STATE/run.log" | tail -1)
  [[ $url == http* ]] || { note "record PR: could not open it (see run.log)"; return 0; }
  if [[ $MERGE_POLICY == auto ]]; then
    if $GH pr merge "$url" --merge --match-head-commit "$head" > /dev/null 2>> "$STATE/run.log"; then note "record PR merged into $MAIN_BRANCH · $url"
    else note "record PR: the merge was refused; left open · $url"; fi
  else note "record PR opened; left for Michael (MERGE_POLICY=$MERGE_POLICY) · $url"; fi
  rec_commit "HARNESS: record PR"; sync_record
}
```

The branch is record-only (D3 of P1, `rec_commit_` stages `.harness/runs/<run>/` only), so its PR's diff is
`.harness/runs/<run>/` and the merge can't conflict. The note commit after the merge leaves the branch one record
commit ahead of main, which `gc`'s `record_only` already treats as done. `finish` deletes nothing: no
`--delete-branch`, so `harness continue <run>` the same night still finds `harness/<run>` on origin (D4).

## 6. Visibility and prompts (P2-06)

- **`harness status <run>`**, for a running run, before its unit lines (which keep their text: `08`'s check reads
  `    harness-termed-M1-s[0-9]+ · MemoryCurrent 50 MB`), one line per lane with a live pid:
  `    lane <m> · <feature> · session <n> · port <p> · slot <k> · <units and MemoryCurrent>`, where `<feature>` and
  `<n>` come from `$STATE/lanes/<m>/now` (`<id or "verify <m>" or "re-base <m>">\t<scope-seq n>`, written by
  `session()` when `LDIR` is set, `record.sh:203`), `<p>` from `lanes/<m>/port`, `<k>` from `lanes/<m>/slot`'s
  `slot-<k>`, and the units as `s3 412 MB, svc 80 MB` (the lane's `harness-<run>-<m>-*` units, their `MemoryCurrent`)
  or `no units`.

  trends` reads `runs.jsonl`, unchanged; its check keeps its text.
- **The brief's note.** `lib/check.sh` appends `<start $EPOCHREALTIME>\t<seconds>\t<ran|cached|subset>` per call to

  ends (so `run_init`'s suite before and the driver's `green` after never count, whole seconds would blur them). The
  lane then notes `<id>: suite ran <n>x (<s> s) in the session`: `n` the calls between the two stamps that ran (full

- **Prompts.** `prompts/initializer.md`: milestones that may run side by side should touch different files; shared
  docs (`README.md`, `docs/architecture.md`) are edited in a milestone's closing review feature; a feature independent
  of its predecessors in the same milestone gets `after`; and (the brief) a target number in a step is "measured and
  recorded", not "under N", unless the step says it protects the box. `prompts/parts/run.md`: one line, other lanes of
  this run work in other slots (other worktrees, ports and branches); this session's are the ones above.
