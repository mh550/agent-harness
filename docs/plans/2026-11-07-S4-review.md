# S4 review: the purity moves, read branch by branch against the bash they replaced

*(2026-11-07, run `agent-harness-2026-11-07`, feature S4-05. One round by an Opus reviewer, which read the milestone diff
from a file (`git diff 055de2c -- bin lib tests docs journal README.md`, 3,222 lines) with the base tree's bash beside it.
No Critical finding, so no second round. Decision file: `journal/decisions/2026-11-03-purity.md`.)*

## What the reviewer ran

The reviewer compared the old bash (from `git show 055de2c:…`) with the new functions on the same inputs, as differential scripts in scratch:

- the suite runner, `lib/check.sh`, end to end: 122 scenarios (cached markers, odd red marker bodies, every `CHECK_RERUN`
  value, timeouts, signal codes, flakes, `--fast`, subsets, 35 rows of the partial table with corrupted sidecars);
- a finished lane's exit (`lane_done` → `laneDone`): all 512 subsets of its nine marker files, under two merge policies, 1,024 comparisons;
- the verify verdict (72), a reason's card, priority and desk (`endKind`, 23), the run's end lists (`runEnd`, 864),
  the closed lane's exit file (`closedLane`, 30), the queue entry's bytes (`queue_add`, 105) and its decoding (13).

All of them matched on valid UTF-8, apart from the findings below. The finding that mattered is what the bash does
**when a question gets no answer at all**: the resident helper and the plain `node` spawn behind it both fail (an OOM kill, no
process slot, node gone). Old bash had no node call at several of these moments, so it could not take a wrong branch there.
