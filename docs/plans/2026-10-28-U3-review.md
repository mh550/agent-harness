## Important

1. **A multi-line brief broke its queue entry.** Entries hold one argument per line (`queue_add`'s `printf '%s\n'`, the
   runner's `mapfile -t`). A `--brief` with a newline became several arguments, and the runner's
   `harness start … --brief line1 line2` died `unknown option line2` after moving the entry to `done/`, so the start
   was lost. U3-05 made this common: every plain start or continue of a busy project now queues, and a continue queues
   `--brief-file` as its text. **Fixed:** `queue_add` writes a newline inside an argument as `\x1f`. The runner,
   `entry_overlaps` and `status.mjs argsOf` read it back, and queue list's brief head shows it as a space.
   Checks: *a multi-line --brief is one argument in its queue entry …*, *a continue queued behind a live run keeps a
   multi-line --brief-file as one --brief*, *the runner starts that entry with its brief whole …*.
2. **An overlap made an ended run's worktree dirty for good.** `overlap_open` on the other run R wrote `needs.md`
   (needs.mjs `writeMd`) and a `harness-log.md` line into R's record. An ended R gets no record commit, so its worktree
   stayed dirty. gc skips a dirty worktree silently, so it kept it after R merged, and the item, which gc's sweep
   resolves once the worktree goes, stayed open too. **Fixed:** for an R with no live driver or lane, `overlap_open`
   passes no `record`, so there is no `needs.md` and no log line. The record lives in R's state dir and its `run.log`
   line. A live R, and the new run, are as before.
   Check: *an overlap with an ended run records on it in its state only: its worktree stays clean, so the runner's gc
   removes it*. 70-overlap now reads both runs' `run.log` lines, and no `harness-log.md` line on the ended ov1.
