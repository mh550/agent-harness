## The hardest question: did retiring `memlint-self` lose an assertion?

The deleted file's one check made two assertions:
- **(a)** `".harness/config.sh"` and `"docs/decisions.md"` sit on one line each of `lib/memlint.mjs`.
- **(b)** `node lib/memlint.mjs <this checkout>` prints nothing.

**(a): fully covered.** The successor `memlint: the store lookup is decisionsStore, the one function reading
.harness/config.sh and docs/decisions.md, each on one line` is in `tests/unit/memlint.test.mjs` and in both fixtures.
It counts lines the way `grep -c` does, and it also checks that both literals are inside `decisionsStore`'s reach.

**(b): partly lost (I1).** `capCheck` reads only `lintText`'s `size` and `gotchas` findings. A tier-1 op carrying a
stored count (`~1,870 tests`) or a run-scope word (`this run`) passed the gate that was meant to replace the lint.
Under `MEMORY_POLICY=auto` that op would land on main with no one reading it. The decisions-store lint of this repo
also had no suite successor. The lines (b) executed are still run by the `sameAsCli` cases and `memlint-run`, so the
coverage claim held. The assertion's claim did not.
