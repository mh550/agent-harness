- **Denied (`~/.claude/settings.json`):** only what can't be undone or reaches production without a gate:
  - force-push, and any push that rewrites `main`;
  - `git filter-branch` / `filter-repo`;

    project file restates either.
- **Allow rules matter in auto mode.** Docs checked 2026-10-24:
  - Auto mode drops blanket allows (`Bash(*)`, wildcarded interpreters) but keeps narrow ones.
  - Its classifier blocks merging an unapproved PR and deleting remote branches, unless there is an explicit allow.
  - So `permissions.allow` needs `Bash(gh pr merge:*)`, `Bash(git push origin --delete:*)`, `Bash(git branch -D:*)`,
    `Bash(git worktree remove:*)`, `Bash(git worktree prune:*)` and `Bash(docker compose:*)`. Alternatively use
    `autoMode.environment` in user settings; project files can't set it.
    Updated in place 2026-10-24 (n8n-home catch-up, docs re-checked): an allow resolves without the classifier and
    rule specificity doesn't matter, so `Bash(git:*)` and `Bash(gh pr:*)` already cover those; the narrower allows
    were removed from the user file. Read-only commands and edits in the working directory need no rule, and
    `defaultMode` in a project file is ignored.
  - Deny always beats allow across scopes, so the user file must not deny what a project needs.
