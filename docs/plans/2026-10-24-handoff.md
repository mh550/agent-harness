## Policy (what chunk 1 writes down, and what every later session follows)

- **One home.** Write the policy into `~/.claude/CLAUDE.md` § "Git, merges and permissions". It is the only file
  that loads in every session, harness worktrees under `~/worktrees` included. Project files and prompts point at
  it and don't restate it.
- **Allowed for agents:** merges (with or without a PR), pushes, deleting merged branches and worktrees,
  `harness gc`, and `docker compose` for test stacks.
- **Denied (`~/.claude/settings.json`):** only what can't be undone or reaches production without a gate:
  - force-push, and any push that rewrites `main`;
  - `git filter-branch` / `filter-repo`;
  - `git reflog expire` / `reflog delete` and `git gc --prune`;
  - `gh repo delete`;
  - `sudo`;
  - reads of `.env` and `/etc/restic`.
- **Allow rules matter in auto mode.** Docs checked 2026-10-24:
  - Auto mode drops blanket allows (`Bash(*)`, wildcarded interpreters) but keeps narrow ones.
  - Its classifier blocks merging an unapproved PR and deleting remote branches, unless there is an explicit allow.
  - So `permissions.allow` needs `Bash(gh pr merge:*)`, `Bash(git push origin --delete:*)`, `Bash(git branch -D:*)`,
    `Bash(git worktree remove:*)`, `Bash(git worktree prune:*)` and `Bash(docker compose:*)`. Alternatively use
    `autoMode.environment` in user settings; project files can't set it.
  - Deny always beats allow across scopes, so the user file must not deny what a project needs.
- **Production gates (project `.claude/settings.json`, the only project files kept):**
  - **portfolio_site:** deny `vercel`, `npx vercel`, and merging or pushing into `main`. Vercel deploys `main`, so an
    agent proposes the PR with its preview URL and Michael merges it.
  - **n8n-home:** deny `scripts/deploy.sh`, Edit/Write under `//srv/**`, `docker * n8n-n8n-1*`, and the live n8n MCP
    write tools. Allow `docker compose` for `n8n-test-*`.
  - **Everyone else:** no project settings file.
- **Harness merges:** `MERGE_POLICY=auto` in `~/.config/harness/config.sh` (the PR #8 opt-in; this plan first said
  `merge`, a value the harness doesn't know), and `MERGE_POLICY=pr` in portfolio_site's and n8n-home's
  `.harness/config.sh`.
- **Worktrees stay.** Claude Code enforces them for isolated sessions and they can't be switched off (docs,
  worktrees.md). The rule is "finish in the worktree, then merge to `main` yourself".
