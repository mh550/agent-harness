## 4. render.mjs: the `{{SECTIONS}}` line (E3-03)

- A template line that is exactly `{{SECTIONS}}` is where the sections go. Output = fill(the template above it) +
  the sections + fill(the template below it), joined as today (`\n\n`). Without the line, the sections are appended
  at the end as today, so `debrief.md` (`--raw Context=…`) and every other caller are unchanged. Only the first such
  line counts.
- Exported pure function `assemble(template, sections, env)` → string, where `template` is the template's text,
  `sections` is an array of `{ title: string | null, body: string, raw: boolean }` (the CLI reads the files), and
  `env` maps `HARNESS_X` names to values (the CLI passes `process.env`), the CLI guarded the way `metrics.mjs` does
  (`fileURLToPath(import.meta.url) === resolve(process.argv[1])`). That makes it unit-checkable with
  `node --input-type=module -e`. Section bodies are filled unless `--raw`, as today; `{{SECTIONS}}` is never looked up
  in the environment.
- `prompt()` order (not retro; the retro gets `parts/rules.md` only): policy, `prompts/parts/run.md`, brief (if any), `prompts/parts/rules.md` (if CLAUDE.md),
  `.harness/project.md` (if any).

## 6. Init output: the last 40 lines plus the path (E3-02)

```bash
HARNESS_INIT_OUTPUT=$( [[ -f $SCRATCH/init.out ]] && { tail -n 40 "$SCRATCH/init.out"; echo "full output: $SCRATCH/init.out"; } )
```

- 40 lines replace `tail -c 4000`; lines are not cut (GNU `cut -c` counts bytes and would split UTF-8, and the spec's
  rule is lines). The last line is `full output: <path>` (the session can `cat` or `grep` it, since it is in its own
  scratch directory).
- `init.out` already ends with `(init exit N)` and `check.sh`'s summary. A red suite prints its own last 25 lines and
  the path of `check.out`, so the 40 lines hold what the session needs first.
- The fenced block in the template is `` ``` `` / `{{INIT_OUTPUT}}` / `` ``` ``. The check counts the lines between
  the fences: at most 41.

## 7. The time and budget line (E3-04)

`HARNESS_CLOCK`, rendered as `{{CLOCK}}` on its own line in part 4 of coding.md and verify.md, right after the id
lines. The exact wording:

```
Clock: 2026-10-21 22:05 · run 3h10m of 8h, ends 03:55 · this session: $20 budget, 250 turns, 100m timeout · attempt 2 of 2
Clock: 2026-10-21 22:40 · run 3h45m of 8h, ends 03:55 · this session: $20 budget, 250 turns, 100m timeout · verify round 2 of 2
```

- `now` is `date '+%F %H:%M'`. `T0` is the driver's start epoch: line 56 becomes `T0=$(date +%s); DEADLINE=$(( T0 +
  HOURS * 3600 ))`, so the total can't come out as `7h59m`. A `harness continue` starts a new driver with a new
  `T0` and `DEADLINE`, so "run 3h10m of 8h" is this driver's segment. The deadline is the segment's too; that is the
  one that ends the session's run.
  Elapsed is `now - T0` as `<h>h<mm>m` (`0h05m`). The total is `DEADLINE - T0`: `8h` when it is whole hours, else
  `6h40m` (a `DEADLINE_AT` cut). `ends` is `date -d @$DEADLINE +%H:%M`.
- `$SESSION_BUDGET_USD`, `$MAX_TURNS` and `$SESSION_TIMEOUT` are printed as configured (`$20`, `250 turns`, `100m`).
- Coding: `attempt N of $MAX_ATTEMPTS`, where N = `jq -r --arg id "$id" '.[$id] // 0' "$ATT"` after `F bump`. A
  verifier's re-queue (`F grant`) sets the count to `MAX_ATTEMPTS - 1`, so that retry reads `attempt 2 of 2`. Verify:
  `verify round $rounds of $MAX_VERIFY_ROUNDS` (the same round for the escalated model's re-run).
- A driver function `clock <tail>` prints the line. The call sites are
  `HARNESS_CLOCK=$(clock "attempt $a of $MAX_ATTEMPTS") HARNESS_FEATURE=… prompt coding` and the verify one. The
  initializer and retro get no clock (`{{CLOCK}}` isn't in their templates).

## 11. Decisions (journal/decisions.md)

- **D-H36 · No double CLAUDE.md** (E3-02). *Finding:* every worktree session got CLAUDE.md twice, once auto-loaded
  and once pasted (§0; 2682 B here). *Choice:* the prompt names it in one line; `.harness/project.md` is still pasted;
  the debrief, which runs outside any project and pastes none, is unchanged. *Rejected:* keeping the paste "to be
  safe" (it costs tokens every session, and the two copies drift when the file changes mid-run); `--setting-sources`
  to stop the auto-load (interactive sessions read the same file, so it should be the one copy).
- **D-H37 · Static first, a fixed first line, each prompt kept** (E3-03). *Finding:* the id on line 1 left zero
  shared bytes between sessions, and only the last prompt per kind was kept. *Choice:* §1's order, the `{{SECTIONS}}`
  line, the §3 first lines, exact-match stub keys, `logs/*.prompt.md`. *Rejected:* two template files per kind (twice
  the files, for one split point); `--append-system-prompt` for the static part (see the note below; a bigger change,
  candidate for the retro). *Caveat recorded with it:* the API caches at content-block boundaries where a breakpoint
  was written, and `claude -p "<text>"` sends the prompt as one block. A byte-identical prefix *inside* that block
  may therefore not be a cache hit by itself. It makes the prompts diffable and is the precondition for any split
  that would hit. E2's eval says which (first-turn `cache_read` of session 2 vs session 1, from E1's telemetry).
- **D-H38 · The clock line and bounded init output** (E3-02 writes the init-output half, E3-04 the clock half).
  *Finding:* sessions can't tell time, budget or attempt ("Claude can't tell time", per Carlini), and init output was
  4000 B cut mid-line. *Choice:* §7's one line; §6's last 40 lines plus the path. *Rejected also:* a per-line
  `cut -c` (it splits UTF-8). *Rejected:* pasting
  the whole of `init.out` (unbounded); a clock in the static part (it would break the shared prefix); a per-turn clock
  (the CLI has no hook for it in `-p`).
