# A1 · Review of the event hook (2026-11-07)

Run `agent-harness-2026-11-07-3`, feature A1-03. One round, an Opus subagent reading
`git diff $(git merge-base HEAD origin/main) -- lib bin tests templates` (A1-02 and A1-03, 652 lines, the new files
included), asked three questions: does any kind reach the wrong route, are ntfy's arguments unchanged with `EVENT_URL`
unset, and can `NTFY_TOKEN` reach an event POST.

**Verdict: no Critical or Important findings.** Nothing was changed for this review: no RED→GREEN round was needed.

## The three questions

1. **The route: right for every call site.** `needs_notify` passes the caller's `"$@"` before the record's five
   fields (title, body, click, priority, actions), so a call site's `kind=`/`feature=` survives both its branches.
   The parser keeps the last non-empty `kind=`, so an empty one keeps the default `other`, which is never routed.
   The routing `case` matches exactly, and `paused` is never routed. Every call site matches the plan's §3.1
   table; `$ekind` is only ever `ended` or `blocked`.
2. **`EVENT_URL` unset: byte for byte.** The ntfy `a=(…)` array, the data's ` @` guard, the curl line and the
   `NOTIFY_CMD` call are untouched. The routed branch short-circuits on the empty `EVENT_URL`. A fallback changes none
   of notify's locals. tests/checks/event-run.sh's `with EVENT_URL unset a park's ntfy post is the fallback's` and
   event-hook.sh's (a)/(c) diffs prove it.
3. **The token: never sent.** The event curl builds its own arguments: no `Authorization` header and no
   `NTFY_TOKEN`, with stderr to /dev/null. Its two lines carry only the kind, id, code or curl exit.
