## M3-02 · `MEMORY_POLICY=pr|auto|off`

**Code.**
- `lib/config.sh:58`: `MEMORY_POLICY=pr   # pr = tier 1 on harness-memory/<run>, its PR left for Michael; auto = that PR
  merged by the driver; off = no curator (separate from MERGE_POLICY)`, beside `RECORD_PR`.
- `curator()`: `case $MEMORY_POLICY in off) return 0 ;; pr|auto) ;; *) note "memory PR: MEMORY_POLICY=$MEMORY_POLICY is
  none of pr, auto, off; treated as pr"; MEMORY_POLICY=pr ;; esac` (*default*: run as `pr`, the safe value, rather than
  skip the curator). The old `neither pr nor off` note goes.
- `memory_pr`: after a push that reached a PR (`memory_edit` on the reused URL, or `memory_open`), under `auto`
  `memory_merge "$url" "$(git -C "$w" rev-parse HEAD)"`: `origin_t $GH pr merge "$url" --merge --match-head-commit
  <head>` → `memory PR merged into $MAIN_BRANCH · $url`, else `memory PR: the merge was refused; left open · $url`.
  `memory_open`'s note names the policy it ran under (`left for Michael (MEMORY_POLICY=pr)` stays the `pr` text; under
  `auto` the open is not noted as left, the merge note follows). A no-tier-1-change path never merges (*default*: a
  body-only refresh has nothing to merge). The branch is never deleted, as `record_pr` (*default*).
- `MERGE_POLICY=off` still means no memory PR at all (no GitHub writes), whatever `MEMORY_POLICY` says; otherwise the two
  are independent.
- `templates/project/config.sh` and `templates/user/config.sh`: `# MEMORY_POLICY=pr   # pr · auto · off: …` one line.

**Stub knobs.** None new: `STUB_CURATOR_OPS=three-ops` and `STUB_FACTS=A,B` give the two facts; `STUB_REFUSE_MERGE=1`
refuses the merge (stub-gh's live GraphQL line).

**Checks written first** (slow, `tests/checks/memory-branch.sh` unless named):
1. `memory PR: MEMORY_POLICY=auto merges the memory PR into main and notes it` (the tier-1 commit `on_main`, the note).
2. `memory PR: MERGE_POLICY=auto merges the milestones and leaves the memory PR open under MEMORY_POLICY=pr`.
3. `memory PR: a refused auto merge leaves the memory PR open with one note`.
4. `curator: an unknown MEMORY_POLICY is one note and the curator runs as under pr` (`tests/checks/curator-run.sh`).
5. Replaced: `curator: MEMORY_POLICY=off runs no curator and writes no curator note` →
   `curator: MEMORY_POLICY=off runs no curator and writes no curator or memory note` (same file; the old name leaves
   the fixture in the same commit).
The existing `memory PR: the PR is opened and left for Michael under MEMORY_POLICY=pr` already asserts `pr`'s note.

**Decision row:** the three values, `pr` the default, why separate from `MERGE_POLICY`, the unknown value as `pr`
(*default*), never deleting the branch (*default*).
