## Confirmations the plan asks for (§9)

**No path under `lib/eval.sh` reaches GitHub or ntfy.** The reviewer ran `grep -nE 'gh |curl|NTFY|push' lib/eval.sh`,
and I re-ran it after the fixes:

```
45:  echo "NTFY_URL='' NTFY_TOKEN='' NOTIFY_CMD='' DESK_URL='' DEBRIEF_PAGE_CMD=''"
62:  # HARNESS_EVAL_GH/CURL: the suite's logging stubs; otherwise any call that slipped through fails instead of posting
97:     && git -C "$clone" remote remove origin && seal "$clone" && git -C "$clone" remote add origin "$o" && git -C "$clone" push -q -u origin main; then
105:       && git -C "$clone" push -q -u origin "harness/$run" && git -C "$clone" checkout -q main; then
```

(The reviewer's run, before `seal()` was added, had the same four hits at :45, :62, :89 and :97.) What each one does:

- `:45` `safety()` writes empty ntfy, notify and desk settings into the runs' user config and into every `run.env`, which beats a project's own `.harness/config.sh`.
- `:62` is a comment.
- `:97` and `:105` push only after `remote remove origin && remote add origin "$o"`, so the remote is the local bare `$E/<unit>/origin.git`.
- Not matched by the grep: `run_env` sets `HARNESS_GH=${HARNESS_EVAL_GH:-false}` and `HARNESS_CURL=…:-false`, so any `gh` or `curl` call by a driver fails instead of posting.
- Followed through the driver:
  - `merge_milestones` returns at once under `MERGE_POLICY=off`.
  - `deploy_status` finds no GitHub slug for a path origin.
  - The ledger goes to `$E/ledger` with `LEDGER_COMMIT=0`.
  - `RETRO=0`, `AUTO_CONTINUE=0`, `DESK=0`, and `--foreground` uses no tmux.
  - The 7754661 guard keeps out refs whose driver wouldn't honour any of this.
- The probe runs `claude` with `--tools ""` and calls no `gh` or `curl`.
- The check `eval run: nothing reaches a remote` asserts that `gh.log` and `curl.log` don't grow.

Residual risk, outside `eval.sh`'s control: replayed sessions are real Claude sessions with Michael's user settings,
so their own Bash tool could call `gh -R owner/repo` or `curl`. `git push` and `gh pr create` find no GitHub remote
in the clone. This is as `decisions/2026-10-21-eval-run-isolation` records.

**The trap removes the temp worktree:**
- On a failing task: rc ≠ 0 is logged, and the loop reaches the explicit `worktree remove`.
- On a skipped task: removal happens before the `exit 1`.
- On every `die` after `worktree add`: the EXIT trap removes it.
- On an interrupted eval: INT/TERM run `exit 130`, then the EXIT trap. The new check covers this.

**`lib/prompt.sh` changed no prompt byte.** The reviewer diffed `prompt()` and `load_config`'s export block at
`7b69ed3` against `prompt_render` and `prompt_env`: identical, and the `prompt_vars` expressions are identical too.
The existing prompt checks pass.
