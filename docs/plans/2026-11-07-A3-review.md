## The four questions

1. **Text and brief reach a command only as argv: holds in `lib/requests.sh`, but the brief did not hold downstream (C1, I1).**
   - The answer text is one quoted argument (`lib/requests.sh`'s `"$H" answer "$run" "$text"`).
   - `cmd_answer` parses no options and writes `printf '%s\n' "$*"` (`bin/harness:677`). `take_answers_` copies it with `cat`.
   - Nothing evaluates either value: no `eval`, `bash -c`, `printf %b` or here-string. `$(cat; printf x)` keeps trailing newlines.
   - The brief's problem was where `queue add` and `continue` store and read it, after `requests.sh` had passed it on correctly.
2. **No path escapes: holds.**
   - `id` passes `ID_RULE` before `r.id` is set (`lib/requests.mjs` `validateRequest`).
   - `run` passes `RUN_RULE`, then must be in the run list. That list comes from the `*/*/meta.env` glob, which matches no `.` or `..`.
   - A name taken from the file name passes the id rule in node (`resultName`) and again in bash.
   - File names travel NUL-separated, every `mv` has `--`, and a symlink is moved, never read (M5 closes the last gap).
3. **At most once: holds.**
   - `flock` on `requests/.lock` is held for the whole call, and `find` and `validate` both run under it.
   - The claim, `done/<id>.request.json`, is taken before the call runs, and `doneIds` counts a claim as done.
   - So the same id twice in one pass is a duplicate.
   - A crash between the claim and the result left no result at all (M1, fixed).
4. **The 10 s grace: holds.**
   - Age is `now − mtime`. `now` is the integer `date +%s` (or `HARNESS_NOW`), so the age is rounded down, which only delays a rejection.
   - The file is read before it is stat'ed, so a write landing in between makes it look younger, not older.
   - A JSON object can't parse before its closing `}`, so no half-written file parses.
   - Only a future mtime misbehaves (M7, not fixed).

## Simplifications

- The `node -e` import of the refusal is gone (M2). `result` takes its node arguments as they come (`--refused <why>` or
  `--backup-window 1`), instead of a seventh positional argument re-wrapped into an array.
- Kept on purpose: the bash `ID_RULE` re-check of node's `name`. It is the one test that guards a path built in bash, so
  it stays in front of every `done/<name>` even though `resultName` applies the same rule.
