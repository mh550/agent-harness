## 2. `harness desk <run> [--why "<one line>"]`

### 2.1 Order of work

1. **Arguments.** `<run>` is checked like `state_of` in bin/harness (same regex `^[A-Za-z0-9][A-Za-z0-9._-]*$`, same
   `harness: no run '<id>' …` message, exit 1); desk.sh carries its own three-line copy (as debrief.sh carries its
   own `alive`). A run named `debrief` is refused (`use harness desk --debrief`), it would share the debrief's window.
   `--why`: control characters → spaces, trimmed, at most 200 characters (cut with `…`); optional (empty is allowed).
   Unknown option: usage on stderr, exit 2. Nothing is created before the arguments are good.
2. **State.** `source <state>/meta.env` (PROJECT_DIR, WT, RUN_ID, STATE); `harness_config "$WT" "$STATE"` (a project may
   set `DESK_MODEL`); `D=$STATE/desk`; `S=${HARNESS_DESK_SESSION:-h-desk}`, `W=$RUN_ID` (the window name is the run id
   as is; every tmux target after creation is the window id `@N`, so dots, prefixes and look-alike names never matter).
3. **Lock.** `exec 8> "$STATE_ROOT/desk.lock"; flock -w $(( WAIT + 10 )) 8` (two drivers may start desks at once;
   both would try `new-session`). Not taken in time: plain notification (§2.5) with the note
   `desk: another desk start held the lock; plain notification`. **Every tmux call in desk.sh runs with `8>&-`**: the
   first call may start the tmux server, and a server that inherited fd 8 would hold the lock forever.
4. **Prompt.** `mkdir -p "$D"`; `P=$D/<stamp>.md`, stamp `date +%Y%m%d-%H%M%S`, `-2`, `-3` … appended when that file
   exists (two events in one second keep both prompts); rendered from `prompts/desk.md` (§5); `date +%s > "$D/last-event"`.
5. **Reuse or start** (§2.3). Start → **wait** (§2.4) → URL found: `echo "$URL" > "$D/url"`, `sleep 1` (the TUI takes
   input once it is drawn), type `Read <P> and follow it.` (§3) → record (§2.6) → notify (§2.6) → print the URL.
6. **Exit.** 0 whenever Michael got a notification (desk or plain); 1 for an unknown run, 2 for usage. A desk that
   fails is never an error exit beyond that: its caller (the driver) must not have to care.

stdout is exactly the URL line (or nothing when there is no desk); one line on stderr says why there is none.

### 2.2 The claude command

```
<claude> --remote-control "desk · <run> · <why>" --model <model id> --add-dir <worktree>
```

- `<claude>`: `${HARNESS_CLAUDE:-claude}` resolved with `command -v` to an absolute path (the pane's PATH is the tmux
  server's, not ours). Tests export `HARNESS_CLAUDE=$HERE/stub-claude.sh`, so **no test path can start a real claude**.
- The name: `desk · <run> · <why>`, or `desk · <run>` when the why is empty (`desk · debrief` for §2.7).
- `<model id>`: `node lib/features.mjs model "$DESK_MODEL"` (opus → `claude-opus-5-5`).
- `--add-dir <worktree>` only when `$WT` exists (a gc'd run's desk can still read the state and the ledger).
- No `--permission-mode`: the session runs in Michael's default (auto), as verified by hand.
- The window's working directory is `$PROJECT_DIR` (`~/projects/<project>`, trusted; a fresh worktree is not and its
  trust prompt would block the session).

**Environment.** tmux starts window commands in its server's environment, not ours (the reason for bin/harness's
pass list at line 153). The window command is

```
env -u NTFY_TOKEN [-u V]… [V=<value>]… <claude> --remote-control <name> …
```

passed to tmux as **separate arguments** after the options (`new-window … -- env … "$claude" --remote-control "$name" …`;
tmux 3.4 then runs it directly, no shell: tried with a name holding `·`, spaces and `$(x)`, which arrived verbatim), so
nothing is quoted with `printf %q` (under a C locale `%q` turns `·` into `$'\302\267'`, which only bash reads). For each
`V` in `HARNESS_STATE HARNESS_WORKTREES HARNESS_CONFIG HARNESS_LEDGER HARNESS_CLAUDE HARNESS_GH HARNESS_CURL
STUB_DIR STUB_DESK_NO_URL`: `V=<value>` when set in desk.sh's environment, else `-u V` (a server started
by an earlier call must not leak that call's `STUB_DESK_NO_URL` into this window). `-u NTFY_TOKEN` always: the window
also inherits the tmux server's global environment, and a token exported in Michael's login shell must not reach the
pane (its environment is visible to `ps`). Nothing else is added.

### 2.3 Find, reuse or start the window

```bash
tmux list-windows -t "=$S" -F '#{window_id}'$'\t''#{window_name}'$'\t''#{pane_dead}' 2> /dev/null 8>&-   # → the line whose name is exactly $W
```

`=` makes the session match exact: without it `-t h-desk` matches a session `h-desk-x` by prefix (tried on tmux 3.4).

- **Alive** = a window named `$W` exists, its `pane_dead` is `0`, and `$D/url` is non-empty. Then (P3-03): type
  `New since your last brief: <why>. Re-read <P>.` (why empty: `a new event`), notify with the same URL
  (`$(cat "$D/url")`), record `desk: sent to the open desk: <url> (<why>)` (not `desk started:`, so "one desk" is
  countable), print the URL, exit 0. No wait, no new window.
- **Dead** (window exists, pane dead or no URL file): `tmux kill-window -t <id>`, `rm -f "$D/url"`, then start,
  choosing new-session or new-window by a fresh `has-session -t "=$S"` (killing the only window ends the session).
- **None**: start.

Start:

```bash
# no session yet
id=$(tmux new-session -d -s "$S" -n "$W" -c "$PROJECT_DIR" -x 250 -y 50 -P -F '#{window_id}' -- "${cmd[@]}" 8>&-)
# the session exists
id=$(tmux new-window -d -t "=$S:" -n "$W" -c "$PROJECT_DIR" -P -F '#{window_id}' -- "${cmd[@]}" 8>&-)
```

`-x 250` keeps the URL on one line in a session nobody is attached to; `capture-pane -J` (§2.4) joins it anyway when an
existing session is narrower. When the claude in a window exits (Michael types `/exit`), tmux closes the window (the
default `remain-on-exit off`); when the last window goes, the session goes.

### 2.4 The URL wait

```bash
for (( i = 0; i < ${HARNESS_DESK_WAIT:-60}; i++ )); do
  URL=$(tmux capture-pane -p -J -S - -t "$id" 2> /dev/null 8>&- | grep -oE 'https://claude\.ai/code/session_[A-Za-z0-9]+' | tail -1)
  [[ -n $URL ]] && break
  tmux list-windows -t "=$S" -F '#{window_id}' 2> /dev/null 8>&- | grep -qxF "$id" || break   # claude exited: no point waiting
  sleep 1
done
```

`-S -` reads the scrollback too (the line may have scrolled by the time we look); `-J` joins wrapped lines.

### 2.5 No URL in time (P3-03): kill, log, plain notification

`tmux kill-window -t "$id"`; record `desk: no session URL within <WAIT> s; killed the window; plain notification`;
notify title `[<run>] needs you: <why>`, priority high, tags `question`, click = the INBOX.md blob URL (`gh_url`, run in
`$WT`; nothing on a non-GitHub origin), body as §2.6 without the desk lines. stdout nothing; stderr
`no desk (no session URL within <WAIT> s); notified`; exit 0. The same plain path covers `tmux` missing
(`desk: tmux not found; plain notification`) and the lock (§2.1.3).

### 2.6 Record and notify

- **Record**: `log` appends `<date> <text>` to `<state>/run.log` (no `tee`: stdout is the URL); `note` also appends
  `- YYYY-MM-DD HH:MM · <text>` to `$WT/.harness/runs/<run>/harness-log.md` (the driver's format). Started:
  `desk started: <url> (<why>)`. When the run's driver is **not** alive (`driver.pid`, `kill -0`), desk.sh commits
  that one file (`git -C "$WT" commit -q -m "HARNESS: desk" -- .harness/runs/<run>/harness-log.md`) and pushes
  (`git -C "$WT" push -q origin HEAD`; a failure is a `log` line), so the worktree stays clean for gc. When it is
  alive, the driver's next `commit_all` takes the line (the driver is the caller, or about to commit anyway).
  Worktree gone: run.log only.
- **Notify** (P1's `notify`, `NOTIFY_TAG=$RUN_ID`): `notify "needs you: <why>" title="[<run>] needs you: <why>"
  priority=high tags=question click="<url>" body="<body>"` (no why: title `[<run>] needs you`), body:

  ```
  <why>
  Open the desk: <url>
  Or by hand: harness parked <run>
  ```

  With DESK=1 the driver's own notification (park, end, verify) still goes out first, unchanged; the desk's is the
  second, with the session as the click. (D-H31 *default*: two notifications per event. See §12.)

### 2.7 `harness desk --debrief [--why …]` (P3-03)

Same flow with: `D=$STATE_ROOT/queue/desk`, `W=debrief`, working directory `$HARNESS_HOME` (`~/projects/agent-harness`,
trusted), `--add-dir "$WT_ROOT"` (`${HARNESS_WORKTREES:-~/worktrees}`: the runs the note names) and `--add-dir
"$LEDGER"` when the ledger is outside `$HARNESS_HOME`, `harness_config /nonexistent` (user config only), `log`/`note`
both to `queue/runner.log` (no run record), title `[debrief] needs you` (`: <why>` only when given; the debrief passes
none), body `Needs Michael: <LEDGER>/debrief.md` + the desk lines, no GitHub click on the plain path. The prompt is §5's
debrief block. `<LEDGER>` = `${HARNESS_LEDGER:-$HARNESS_HOME/ledger}`.

## 3. Input to the desk

```bash
tmux send-keys -t "$id" -l "Read $P and follow it." 8>&-
tmux send-keys -t "$id" Enter 8>&-
```

`$id` is the window id `@N` from `-P -F '#{window_id}'` (§2.3): the `<session>:<window>` target resolved once, so `-t h-desk:parky` can never reach a window
`parkyx` by prefix. `-l` types the text literally (no key names); Enter is its own call, as verified by hand (the text is submitted like
typed input). The texts never start with `/` (a slash command) or `-` (an option); the why is one line (§2.1.1). A
later event: `New since your last brief: <why>. Re-read <P>.` the same way.

## 5. `prompts/desk.md`

Rendered by `lib/render.mjs` with `HARNESS_RUN_ID HARNESS_WHY HARNESS_EVENT_AT HARNESS_INBOX HARNESS_PROGRESS
HARNESS_WT HARNESS_PROJECT_DIR HARNESS_BIN HARNESS_NOTE` set only on that command (`HARNESS_BIN` = the absolute
`bin/harness`, `HARNESS_NOTE` = `<LEDGER>/debrief.md`, `HARNESS_INBOX`/`HARNESS_PROGRESS` = absolute paths in the
worktree). The file has two mode blocks, each between marker lines `<!-- run -->` … `<!-- /run -->` and
`<!-- debrief -->` … `<!-- /debrief -->`; desk.sh deletes the other mode's block and the kept block's marker lines
with `sed` after rendering. No secret is ever a variable here (`NTFY_TOKEN` is not passed to render).

Content, in this order (short imperative text, written for a phone-sized chat):

1. **Head**: `# Desk — {{RUN_ID}}`; who you are (the desk for run `{{RUN_ID}}`, an interactive session the harness
   started with Remote Control so Michael can answer from his phone); the event `{{WHY}}` at `{{EVENT_AT}}`; `harness`
   is `{{BIN}}` when it isn't on PATH.
2. **`## 1. Read what is waiting`**: run block: `harness parked {{RUN_ID}}`, `harness status {{RUN_ID}}`, the
   questions above `## Answers` in `{{INBOX}}`, the newest two or three entries of `{{PROGRESS}}`. Debrief block:
   `{{NOTE}}` (the newest `ledger/debrief.md`) and its `## Needs Michael` section, then for each run it names
   `harness parked <run>`, `harness status <run>`, its INBOX.md and progress.md
   (`~/worktrees/<project>/<run>/.harness/runs/<run>/`).
3. **`## 2. Check what can be checked safely`**: files, `git log`/`git status` in the worktree, `docker ps`; whether a
   variable is set **by name only** (`grep -c '^NAME=' file`), never a value; never read or print `.env` contents,
   tokens or keys; no `sudo`; none of the project's live commands (deploys, migrations, writes to a service). Say what
   was checked.
4. **`## 3. Write Michael one brief`**: a headline (what is waiting, since when, what it holds up); then each open
   item numbered, with the context needed to decide, the options, a recommendation and why. Short enough for a
   phone; the numbers are what he answers to ("1 yes, 2 the later edit, 3 skip").
5. **`## 4. After his reply`**: ask a follow-up when an answer is ambiguous; for each item he decided,
   `harness answer {{RUN_ID}} "$(cat <<'HARNESS_ANSWER_END'` / his decision in his words, with the item number it
   answers / `HARNESS_ANSWER_END` / `)"` (his words never reach the shell, P2 review I3); read it back; on his go run
   the `next:` commands `harness parked {{RUN_ID}}` prints (it knows going / ending / queued / a runner); for a run
   that isn't parked (blocked, verify, merge): `harness queue list` → a runner going: `harness queue add --continue
   {{RUN_ID}}`, else `harness continue {{RUN_ID}}`; a run still going needs no continue.
6. **`## 5. Never`**: never answer an item he didn't decide; never edit INBOX.md, feature lists, policies, CLAUDE.md
   or settings directly; never start, stop or merge runs other than the continue above; never `sudo`; never a live
   command; never print a secret.
7. **`## When a new event arrives`**: a line `New since your last brief: <why>. Re-read <path>.` means re-read that
   file and brief only what is new, with numbering that continues the last brief's.

## 6. The stub's interactive mode (`tests/stub-claude.sh`)

**Fixture** `tests/fixtures/remote-control-pane.txt`, two lines:

```
# source: the pane of claude 2.1.303 on 2026-10-19 (tmux, by hand), as quoted in docs/specs/2026-10-19-phone-answers.md § P3; the id is cut there
/remote-control is active · Continue here, on your phone, or at https://claude.ai/code/session_01YSDT…
```

**Mode**: argv has no `-p` → interactive. Detect it in the existing argv loop (`[[ $1 == -p ]] && headless=1`), not
with `printf … | grep -q`: under the stub's `pipefail` a large prompt argument gets `printf` a SIGPIPE when `grep -q`
exits early, and a headless session would be taken for a desk (reproduced in review with a 200 KB argument). This branch goes
**before** `[[ -n $prompt ]] || prompt=$(cat)` (that line would eat the typed input):

1. `mkdir -p "$STUB_DIR/desk"`; `n` = `$STUB_DIR/desk/count` + 1, written back (desks are serialized by desk.lock).
2. `name` = the argument after `--remote-control` (the remote-control name); `<name>` (the file name, used for
   both `.in` and `.args`) = `<n>-` + that name with every run of
   bytes outside `[A-Za-z0-9._-]` squeezed to one `_`, trailing `_` dropped (`LC_ALL=C tr -cs 'A-Za-z0-9._-' _`):
   `desk · parky · B parked: set the gatus vars` → `1-desk_parky_B_parked_set_the_gatus_vars` (a why may hold `/`).
3. `$STUB_DIR/desk/<name>.args`: every argument on its own line, then a last line `PWD=<cwd>`.
4. Unless `STUB_DESK_NO_URL=1`: print line 2 of the fixture with `session_[^[:space:]]*` replaced by
   `session_TEST<n>`. (So the first desk the suite starts is `https://claude.ai/code/session_TEST1`.)
5. `while IFS= read -r line; do printf '%s\n' "$line" >> "$STUB_DIR/desk/<name>.in"; done`; exit 0 at EOF (the window
   is killed: SIGHUP ends it too).

`send-keys` into the stub's pane (a cooked tty) arrives as one line per Enter (tried on tmux 3.4: `Read /x/y.md and
follow it.` came through whole).

## 7. When the driver and the debrief start a desk (P3-04)

One helper in `lib/driver.sh`, next to `needs_you`:

```bash
# DESK=1: a Remote Control session briefs Michael (lib/desk.sh). It never changes the run: a failure is a note.
desk() { [[ $DESK == 1 ]] || return 0; "$HARNESS_HOME/bin/harness" desk "$RUN_ID" --why "$1" > /dev/null 2>&1 9>&- || note "desk: could not start (exit $?): $1"; return 0; }
```

This is the `[[ $DESK == 1 ]] && desk … || note …` shape with the guard split out: written inline as one list, the
`|| note` would also fire whenever `DESK=0`. `9>&-`: the driver's ledger lock fd, never inherited by a tmux server.
desk.sh's own notes (`desk started:`, `no session URL`) land in harness-log.md while the driver waits; its next
`commit_all` takes them. A desk start blocks the driver about `HARNESS_DESK_WAIT` at most, and `2 × WAIT + 10` s (≈ 130 s) in the worst case
of another desk holding the lock (synchronous on purpose: no race on harness-log.md, and the checks can count windows
when the run ends).

**Placement**: each call goes *after* the `[[ -n $(git status --porcelain -- "$RUN_DIR") ]] && commit_all "HARNESS: …
notification failed"` check that follows its notification (driver.sh:529 for the park, the run-end one in `finish`):
desk.sh's own harness-log.md line must not be committed as a "notification failed".

| Where | The call | `--why` |
|---|---|---|
| the park, after `notify_park` and its commit (main loop) | `desk "$id parked: $why"` | `B parked: set the gatus vars` |
| `finish`, after the end notification and its commit, before the retro | `case $1 in "blocked on"* \| "waiting on Michael"*) desk "ended: $1" ;; esac` | `ended: waiting on Michael: B` |
| `needs_you` (verify thin/red/failed, a conflict with main), after its notify | `desk "$1 needs Michael: $2"` | `M1 needs Michael: A fails verification` · `M2 needs Michael: conflicts with main` |
| `merge_one`, the refused branch, after its notify | `desk "$m: merge refused"` | `M1: merge refused` |

A park followed by the run's end reaches one desk: the end is typed into the park's window (§2.3).

**Debrief** (`lib/debrief.sh`, after its `notify`, before `exit 0`): it holds `debrief.lock` on fd 9, so

```bash
[[ -n $NM && $DESK == 1 ]] && { "$H" desk --debrief > /dev/null 2>&1 9>&- || log "debrief: desk could not start (exit $?)"; }
```

(`NM` is the existing non-empty "Needs Michael" test that already raises the priority.)

## 10. Housekeeping (P3-05)

- **`harness desk --list`**: for each window of `=$S` (none: `no desks`, exit 0), one line
  `printf '%-12s %-26s %-50s %s\n' <window> <run> <url> <age>`: `<run>` = the window name when
  `$STATE_ROOT/*/<name>/meta.env` exists, `(debrief)` for `debrief` (its files in `queue/desk/`), else `-`; `<url>` =
  that `desk/url` or `-`; `<age>` = now − `desk/last-event`: `<n> min` under an hour, `<n> h` under two days, else `<n>
  d` (floor), `-` without one. No header line. Read-only.
- **`harness desk --close <run>`**: the window named `<run>` (or `debrief`) killed by id, its `desk/url` removed,
  `closed desk <run>`; none: `no desk for <run>`; exit 0 either way. Unknown run ids are fine here (a window may
  outlive its state).
- **`harness desk --all`**: `tmux kill-session -t "=$S"`, `closed every desk (<n>)`, every `desk/url` under the state
  root removed; no session: `no desks`; exit 0.
- **`harness gc <project>`**: after its branch work, `"$HARNESS_HOME/lib/desk.sh" --gc "$(basename "$p")"` (with
  `--dry-run` when gc has it): for each `$STATE_ROOT/<project>/*/desk/last-event` (and `queue/desk/last-event`) older
  than 24 h whose window is open: close it as `--close` does and print `closed idle desk <run>` (dry run: `would close
  idle desk <run>`). Fresh or windowless desks are left alone.
