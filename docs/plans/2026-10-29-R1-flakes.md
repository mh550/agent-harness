## The tools

### `wait_for <max s> <command…>` (R1-02)

**Where.** `tests/lib.sh`, beside `in_has`. Runs `"$@"` (stdout and stderr to `/dev/null`) every 0.1 s.

**Signature.** `wait_for <max seconds> <command…>`: returns 0 the first time the command exits 0; when `max` seconds
have passed (measured with `$EPOCHREALTIME`, not counted iterations: a loaded box's slow iterations must not stretch
the limit) it prints one line to stderr and returns 1. A function in the caller's shell, so `eval '<expr>'` sees the
check file's variables.

**Output.** Nothing on success. On giving up: `wait_for: <command…> still failing after <max> s` (the command as
`$*`).

**Rewritten on it.** `in_has <file> <pattern>`: `wait_for 30 grep -q "$2" "$1"` (was `seq 20` × 0.1 s). `settle`:
`wait_for 30 eval '! pgrep -f …'` after its start (below, *The sweep*, `lib.sh:73`). `ran`: waits for the next clock
second with `wait_for 2 eval '[[ $(date +%s) -gt $s ]]'` (was `sleep 1`), then writes its lines. Afterwards
`grep -c 'seq 20\|seq 150' tests/lib.sh` prints 0.

**Checks** (`tests/checks/75-suite-tools.sh`, written first, watched failing on a `lib.sh` without the function):
- `suite tools: wait_for returns as soon as its command succeeds (a background touch, well under its 30 s limit)`:
  `( sleep 0.5; touch "$T/wf" ) &  # sleep-ok: the event under test`, then `wait_for 30 test -f "$T/wf"` returns 0
  and the elapsed `$EPOCHREALTIME` difference is below 5 s.
- `suite tools: wait_for gives up after its limit with its still-failing line, exit 1`: `wait_for 1 test -f
  "$T/missing"` returns 1 and its stderr is exactly `wait_for: test -f <path> still failing after 1 s`.

### `stub_wait <name>` / `stub_go <name>` and `STUB_BARRIER` (R1-02)

**Where.** `tests/lib.sh` (the two functions) and `tests/stub-claude.sh` (the knob, in its header comment beside
`STUB_SLOW_CODING`).

**Signatures.** `stub_go <name>`: `mkdir -p "$T/barriers" && : > "$T/barriers/<name>"`. `stub_wait <name> [<max s>]`:
`wait_for "${2:-60}" test -e "$T/barriers/<name>"`, returning its status. `STUB_BARRIER=<id>:<name>`: that feature's
first coding session touches `$STUB_DIR/barriers/<name>.held` (so a check can `stub_wait <name>.held` for "the session
is at the barrier"), then waits (≤ 180 s, the old hold's limit) for `$STUB_DIR/barriers/<name>` before it writes its
entry and ends. `$STUB_DIR` is `$T`, so both sides name the same files.

**Output.** None of their own; `stub_wait` giving up prints `wait_for`'s line.

**Checks** (`75-suite-tools.sh`):
- `suite tools: a stub_wait/stub_go barrier orders two background jobs the same way in 20 of 20 rounds`: per round,
  job 1 `stub_wait r<i>; echo second >> "$T/order"` and job 2 `echo first >> "$T/order"; stub_go r<i>`, started in
  that order; after `wait`, `$T/order` holds `first second` 20 times.
- `suite tools: STUB_BARRIER holds that feature's first coding session until stub_go`: a stub run in the background
  with `STUB_BARRIER=A:a-end`; `stub_wait a-end.held`; A's entry is not in the run's `entries.jsonl` yet; `stub_go
  a-end`; the run ends with A passing. (Not named in R1-02's steps; the project's rule that every behaviour gets a
  check asks for it.)

### The sleep lint (R1-03)

**Where.** `tests/lint-sleeps.sh [<file>…]` (default `tests/checks/*.sh tests/lib.sh`; the stub scripts are exempt:
their sleeps are the work they stand in for).

**Rule.** A line matching `\bsleep\b` (so `sleeps` and `ckt_sleep` don't) that is not a full-line comment (`^\s*#`)
and lacks `# sleep-ok:` is listed. A trailing comment that only *mentions* sleep (`15-…:163`, `47-…:94`) is reworded
or carries `# sleep-ok: text`: the lint doesn't parse comments out of code lines (a `#` inside a string, `$#`,
`#{pane…}`, would fool it).

**Output.** One `<file>:<line>` per listed line, on stdout; exit 1 when it printed any, 0 otherwise.

**Checks** (`75-suite-tools.sh`):
- `sleep lint: a bare sleep is listed as <file>:<line>, exit 1`: a fixture file whose line 2 is `sleep 1` → output
  `<fixture>:2`, exit 1.
- `sleep lint: a sleep with # sleep-ok: passes silently`: `sleep 1  # sleep-ok: x` → no output, exit 0.
- `sleep lint: tests/checks and tests/lib.sh hold no bare sleep`: the lint with no arguments → no output, exit 0.

### `tests/run.sh --repeat <n> <name>…` (R1-02)

**Where.** `tests/run.sh`, parsed before the file list; its usage header gains one line for it.

**Signature.** `bash tests/run.sh --repeat <n> <name>…`: the files matching the names (as today), each run `n` times,
`TEST_JOBS` copies at once (load by design), every copy its own process from its own `suite_setup` (fresh `$T`). No
conformance check (a subset), no `HARNESS_FAILED=` line (a repeat is not check.sh's input). `KEEP=1` keeps each red
copy's `$T` and names it, as today.

**Output.** Per file, after all its copies: `<file>: <k>/<n> green`, then the FAIL lines of each red copy (prefixed
`copy <i>: `). Exit 1 when any copy was red, 0 otherwise. The flaker features run it **directly** in the session
(`bash tests/run.sh --repeat 10 <file>`), never through the suite command, whose timeout is the whole suite's.

**Checks** (`75-suite-tools.sh`, with `TEST_CHECKS` pointing at fixture files):
- `suite tools: --repeat 3 on a file red every other copy prints k/3 green and the red copies' FAIL lines, exit 1`:
  the fixture fails when a counter file (`flock`ed increment) is even; output has `2/3 green` or `1/3 green`, a FAIL
  line, exit 1.
- `suite tools: --repeat 3 on a steady file prints 3/3 green, exit 0`.

Every name above goes into `tests/fixtures/check-names.txt`, `LC_ALL=C` sorted, copied from the PASS lines.

## The sweep: every `sleep` in `tests/checks/` and `tests/lib.sh` (R1-03)

`grep -c sleep tests/checks/*.sh tests/lib.sh` (files with none left out), 96 lines in 22 files. Each line is marked
**poll** (a fixed-iteration wait for a condition: becomes `wait_for`), **order** (one event before another: a barrier
where a stub is the actor, else a `wait_for` on what the actor leaves; a *negative* is "nothing happened over n
polls", which becomes a `wait_for` on the actor having polled n times when it leaves a trace, else keeps its sleep with
`# sleep-ok: a negative over <n> polls`), **work** (the sleep is the thing: a live pid, a pane's process, a stub's slow
step, a fixture's hang: keeps it with `# sleep-ok: <why>`), or **text** (the word in a comment, a pattern or a name:
not a call; a full-line comment needs nothing, a code line gets `# sleep-ok: text` or is reworded). The `STUB_SLOW_*`
sleeps are among the work.
