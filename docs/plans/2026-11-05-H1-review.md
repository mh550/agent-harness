## The spec's hardest points

- **Every failure branch of `ask` ends in a spawn and the right answer, never a hang.** Holds. The read timeout, in the
  header and in the payload (`hx_e > 128`); EOF and a partial header (`hx_e` other non-zero); a short payload (the length
  compare, file 91's `cut` and `short` fakes); a header that is not three fields (the regex); a wrong id; the lock refused
  (`helper_ask`: `flock -n`, `.err` untouched); three restarts then off (`helper_failed`). A late reply can't be read as
  the next answer: the helper is killed on any failed read, and `$SRANDOM` ids catch a killed asker's. rc 64 keeps the helper
  and drops `.err`. `kill -9 && wait` could block on a D-state helper, but the spawn after it would block on the same mount.
  `trap - PIPE` restores the default, not a caller's trap: `lib/` and `bin/harness` have no PIPE trap.
- **No module-level mutable state in a served script.** Holds, the imported `view`, `overlap` and `parked` too: no `let` or
  `var`; module-level Sets, arrays and objects are never mutated; the `/g` regexes (`view.TOKEN`, `overlap.PATHY`, `overlap.TAG`)
  go only through `matchAll` and `replace`.
- **The framing.** Holds. A NUL declines; no trailing newline, multi-byte, over 64 KB (140 KB, 5 MB) come back intact under
  `cmp`, control and invalid bytes in a UTF-8 locale too. Finding 1 was what declining costs a writer, not the framing.
- **No served `main` reads `process.argv`, `process.cwd()`, fd 0 or the start-time environment.** Holds, through imports too:
  `view.home(env = process.env)` reads at call time. No `isTTY`, `columns` or `stdin` in the helper's `io` is what a piped
  CLI has, and no stdin is `NoStdin`, thrown before `inbox insert` or `notify trim` writes. The reader's child-`env` diff, helper
  against spawn, differs only in `_`, `BASH_FUNC_*` and arrays (finding 5); git in `needs` and `overlap` inherits `useEnv`'s.
- **No child holds the helper's pipe.** Holds, with a positive control (the reader's): the shell holds 2; `$(cmd &)`, `( ) &`,
  `func &`, `cmd &`, setsid and `<(exec cmd)` hold 0; a `<(subshell)` holds 2 until it ends. The helper keeps only 0, 1, 2.
- **`lib/helper.mjs` caches nothing between requests.** Holds. `useEnv` rewrites the whole environment and `chdir` runs per
  request; no `main` sets `exitCode`, `umask` or a listener, or uses a timer. Node's import cache keeps code, as the running
  bash does (the spec's accepted `harness sync` case).
