## How measured

- Node starts: `strace -f -e trace=execve -o <f> bash tests/run.sh <files>`, counting `execve` lines whose binary ends in
  `/node` without `= -1`. CPU and wall: `command time -v` (GNU time) user+sys and elapsed of the same command; the same
  with `TEST_JOBS=1`.
- Before set (the baseline §5.3 eleven `-pure-` files by full name): `01-scheduler 02-notifications 03-harness-parked
  04-render-pure 05-metrics-pure 06-test-counts 07-step-lint 11-deploy 12-journal 35-backlog 51-view-pure`.
- After set A (spec wording: `00-unit` + every `-pure-` file left + every file still holding a `node --input-type=module`
  line, `grep -l`: 82-key-map-lint, 84-node-memo): 00-unit-tier + 03 04 05 06 07 11 12 35 51 + 82 + 84.
- After set B (the same without `84-node-memo`, whose 26 checks are stub-run/memo behaviour and take 27.6 s alone, so
  set A's CPU is mostly that file): 00-unit-tier + 03 04 05 06 07 11 12 35 51 + 82.
- The unit tier alone: `node --test --test-isolation=none tests/unit/*.test.mjs` (124 tests), strace and `time -v`.
- Solo full suite: `systemd-run --user --scope -p MemoryMax=3G /usr/bin/time -v env TEST_JOBS=4 bash tests/run.sh`, before
  in the clone, after here, one after the other. (First attempt used `command time` under systemd-run: it cannot run a
  shell builtin there and died in a second; redone with `/usr/bin/time`.)
- Before each timed run `harness status` was run and kept in `status.txt` with `/proc/loadavg`: every one showed
  `RUNNING 1` (this run alone) and `QUEUED 0 · runner going`. Load averages (1 min) before: 1.0–2.0 for the small runs,
  1.5 and 4.6 before the two solo runs (the second right after the first; this session's own just-ended suite), 3.8 / 3.4 before
  set B. This session's own other work was idle during every run.
