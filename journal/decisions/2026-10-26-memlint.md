# memlint: four deterministic checks on a project's memory files, one finding per line

*(2026-10-26, run agent-harness-2026-10-25-memory, feature M4-01; spec `docs/specs/2026-10-25-memory.md` M4, which takes
`docs/specs/2026-10-24-memory-model.md` §K3 as written)*

- **Finding:** the projects' memory drifted in the same four ways (memory-model audit table): CLAUDE.md files past 120
  lines, hand-kept test counts gone stale (dj `CLAUDE.md:16` `~1,870 tests`), night scope in procedural files
  (pathways `.harness/project.md:21` `no rename tonight`), and overturned decisions left standing beside the new rule
  (rane `docs/decisions.md:110` `Superseded in part by D17`, no `Updated in place`). Chunk 3 Part 2 tidied them by
  hand; nothing tells Michael whether that held.
- **Choice:**
  - `node lib/memlint.mjs <worktree>` prints `<file>:<line> <check>: <text>` per finding and exits 0 with or without
    findings (2 on a missing worktree; an unreadable file throws, exit 1). Checks: `size` (CLAUDE.md over
    `MEMLINT_LINES`, default 120, at line cap+1), `gotchas` (over 15 `## Gotchas` lines, a wrapped bullet one line, at the
    16th), `derivable-count` and `night-scope` (CLAUDE.md and `.harness/project.md`), `decisions` (the store
    `decisionsStore` names, the one lookup M2 built).
  - Fixtures are the projects' files as committed before the tidy, trimmed (`tests/fixtures/memlint/`, first line
    names repo, commit, path, read from bare clones in scratch): dj `ed75a2d^`, pathways `4cafb65^`, rane `aa88421^`,
    and tidied files that yield nothing (rane `aa88421` `docs/decisions.md`, rane `3d7abc9` `CLAUDE.md`,
    voice-concierge `99091b5` `docs/decisions.md`). On 2026-10-26 the projects' checkouts give two findings, both
    `size`: hit_list's CLAUDE.md (181 lines) and portfolio_site's (127).
  - *D1 default:* a derivable count is digits before `tests`, `checks`, `passing` or `specs` (`~1,870 tests`,
    `395 checks`), plurals only so a rule ("write 1 test first") isn't one; `checks` is in because this repo's
    CLAUDE.md stored one, removed here. Durations aren't counts.
  - *D2 default:* night scope is `tonight`, `this run`, `this slice`, `as of <date>` (an ISO date or a whole month name or
    abbreviation, so "as of decision 12" isn't one). The
    `## Where things go` section is skipped by both text checks: it is the routing rule itself ("Tonight's scope → the
    brief").
  - *D3 default:* a supersession marker is passive or tagged: `superseded [in part] by`, `[SUPERSEDED]`,
    `is/was/been/now superseded`, `Superseded` opening a line, `overturned by`, `replaced by D<n>` or `replaced by
    decisions/…`. Bare `overturned`, `superseded` and `replaced by` are not: rane's own header says "when a decision is
    overturned", voice-concierge's D11 says "the rows they superseded" (fixture `voice-decisions.md`, 99091b5) and three
    of this repo's decision files say "replaced by" in prose. A file
    store's entry runs from a decision line (the `D<n>` heading, bullet and row shapes of M3's `currentRules`, the same
    id pattern) or a `## ` heading to the next (a `###` sub-heading without a `D<n>` stays inside its entry), and is named by its
    own `D<n>` or its heading; a directory store's entry is a `.md` file (a directory is skipped). The text before the first entry is
    the header, never checked for markers, and must say `current rule set` or `rewritten/edited/updated in place`.
  - *D4 default:* `no store` and `store <path> not found` are reported at `.harness/config.sh` (where `DECISIONS=` would
    go, or its line), since the fix is there or a new `docs/decisions.md`.
- **Rejected:** bare `overturned`/`superseded`/`replaced by` as markers (flags the rule's own wording); checking README or
  architecture docs for counts (the spec names CLAUDE.md and project.md); a count of the store's header lines, not a
  phrase (rane's header is three wrapped lines of prose).
