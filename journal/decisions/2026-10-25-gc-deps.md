# harness gc --deps: the dependency directories of ended runs' worktrees go, merged or not

*(2026-10-25, run agent-harness-2026-10-25-lifecycle, feature L4-03; spec `docs/specs/2026-10-25-resource-lifecycle.md`
§L4 item 3, plan `docs/plans/2026-10-25-L4-gc.md` §3)*

- **Finding:** B8: gc removes only merged worktrees, while `node_modules`, `.next` and `.venv` are 90% of the 7.3 GB
  under `~/worktrees`. An unmerged run's worktree stays (its branch is the work), and so does everything it installed,
  for as long as nobody looks at it.
- **Choice:** `harness gc <project> --deps` deletes the directories `DEPS_DIRS` names (default `node_modules .next
  .next-check .venv`, set in the user's or the project's config; paths relative to the worktree) in the worktrees of
  **ended runs only**, merged or not. A worktree qualifies when git lists it as a worktree of the project, it lies
  under `$WT_ROOT/<project>/`, is not the project's checkout, and its run's state dir (`<state>/<project>/<run>`) has
  `ended`, a `meta.env` whose `WT=` names it, no live `driver.pid`, no queued continuation (`queue/*-continue-<run>.args`)
  and no open desk (`keeps the deps of <wt>: its desk is open`). In it, a named path goes only if it is a directory,
  not a symlink, resolves inside the worktree and holds nothing git tracks, so the tree stays clean and the branch
  keeps every line of work. The output is `+ freed <n> MB in <wt>: <dirs>` (`du -smc` before deleting), `would:
  freed …` on `--dry-run`, `! could not free <wt>: <why>` on a failure, and gc goes on. It runs after the worktree
  removal (a removed worktree has nothing left to free) and before the branch passes. The next `harness continue`
  reinstalls through the project's init.
- **Rejected:**
  - **Deleting in the project's own checkout:** that is where Michael works and where the live harness or a dev
    server may be running from; its `node_modules` is not the harness's to take.
  - **Every worktree without a live driver** (no `ended` needed): a SIGKILLed or crashed run has no `ended` and is
    continued as it was; reinstalling under it mid-run is the init's job, not gc's guess.
  - **Matching worktrees to runs by directory name alone:** `meta.env`'s `WT=` is what the run says it owns; a stray
    directory under `$WT_ROOT` that happens to share a run's name is not touched.
