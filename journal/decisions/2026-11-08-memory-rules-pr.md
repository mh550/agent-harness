- **The three invariants, each with the check that proves it:**
  1. *The curator never writes a project file*: `tests/checks/curator-run.sh` `curator: a curator's edits to CLAUDE.md and lib/ are reverted with one note, its memory-ops.json kept and the record PR opened`; `tests/unit/curator.test.mjs` `curator.mjs: main apply writes the worktree's CLAUDE.md and prints one JSON line` (the rules never written into the worktree, only into the JSON line).
  2. *No operation touches a protected section*: `curator.mjs: an op whose write would change a protected section's lines is dropped` (tier 1) and `curator.mjs: a rules write that would change a protected section's raw lines is dropped` (tier 2); `memory PR: an op on Live system is dropped with a note and carried as a proposal; an unmatched anchor is dropped naming it`.
  3. *The driver never merges tier 2*: `memory rules PR: MEMORY_POLICY=auto merges the facts PR alone and leaves the rules PR for Michael` (no `gh pr merge` of its URL in `gh.log`); `grep -n memory_merge lib/record.sh` shows one call, with the facts URL.
- **Rejected:**
  - **`harness-memory/<run>/rules`**: a ref beneath an existing ref cannot be created (`cannot lock ref`).
  - **Stack the rules commit on the facts commit**: the rules PR would carry the facts and could not merge alone.
  - **Cap each tier alone**: two PRs that each fit can merge into a file past the cap.
  - **Guard `.claude/rules/*.md` only**: Claude Code reads only `.md` there, but two pathspecs where one does, and a
    non-`.md` file a session leaves in a rules directory would stay.
  - **Guard `.claude` itself, so a session that makes `.claude` a symlink is reverted too** (the N1-02 review): the
    pathspec would take `.claude/settings.json`, `agents/` and `skills/` with it, which stay code; a symlinked
    `.claude/` is a deliberate move no session has made, and the curator already refuses to read or write through one.
  - **One shared cap for `CLAUDE.md` and `.claude/CLAUDE.md`**: no project has both, and when one does the pair itself
    is the finding (`twin`); a shared budget would hide which file grew.
  - **Keep the whole-commit refusal, with a clearer note**: the good ops beside a breach are still lost, and the
    curator learns nothing it can act on from one breach for many ops.
  - **Evict on every anchored add** (M2's rule): on a file under both caps it cuts a fact for no reason; the anchor is
    the curator's offer of a line to give up, taken only when the cap needs it.
  - **Order the writes by their position in the file**: the position moves as the writes go (a delete shifts every line
    after it), and the ops' own order is the curator's; a stable sort by kind keeps it within each group.
