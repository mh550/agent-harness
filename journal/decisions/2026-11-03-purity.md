## Finding

The riskiest decisions in the harness are written in bash and reached only by a whole stub run:

- **The suite runner's cache and rerun choices** (`lib/check.sh`): what a red exit means, whether a cached marker
  answers, whether a partial run may stand for the full one, and whether to rerun.
- **The lane's verify verdict and exit table** (`lib/lane.sh`, `lib/driver.sh`): hold, thin, red or fail, and which exit
  code and reason a finished lane gives.
- **How a run ends** (`lib/driver.sh`): which reason, which card, which notification priority.
- **Two formats written more than once.** The queue entry is encoded in one place and decoded in four: `queue_add` in
  `bin/harness` writes it, and `lib/queue.sh`, `lib/spec.sh`, `bin/harness` and `lib/status.mjs` each read it. No check
  holds its newline byte at all. INBOX.md's `status:` line is read three times, with `sed` and `grep`, through `| head`.

Each of these branches costs a stub run to test, and some have no test. The spec's candidates were read on the base tree;
the five below are the decision tables and the twice-written parsers, the spec's *default* order.

## Choice

Each move is the same shape. The logic becomes an exported pure function in the `.mjs` that owns the data, with one unit
test per behaviour. The bash calls it through `ask` (the resident helper, in a driver's or lane's shell) or one `node`
spawn (`lib/check.sh`, `bin/harness`, `lib/queue.sh`, which have no helper) and reads labelled lines. **Every note,
`check:` line, marker byte, flake row, card, exit reason, end reason, queue file byte and runner log line stays as it
is**: every `note "…"` literal stays in its bash file, and a function answers a branch and its values, never a note's
words.

**Defaults taken** (*default*: Michael's to overturn; each is reversible by a commit):

- *Default:* candidates 1, 3, 4, 5 and 6 are the moves, in three build features, as the spec orders them; 2, 7 to 15 are
  left. This is why the bash-removed row (150 or more) is on course to miss: about 90 to 110 gross by the plan's reading.
- *Default:* row 4a of the partial table (only the tree's own map may choose a subset) stays in `lib/check.sh`, because
  it sources `.harness/config.sh`, which only a shell can do. It runs last, so it costs nothing on a call that isn't
  going partial; any refusal runs the full suite, so the order doesn't show.
- *Default:* the subset form became a function, `subset`, defined above the question's one call site and called below it, so the one line that names the module sits below the subset's `exit` and only a killed subset reaches it. A subset killed by its timeout or the cap asks `why` once: it is the only way it can still say which it was.
- *Default:* `lib/checkdecide.mjs` is served by the helper too. `treekey.mjs` stays its own question (two checks count
  its starts), and a lane's `check_run` hands `check.sh` both answers, so a lane's green call starts no more node than it
  did. A red call starts two more (the rerun choice, `guard`, and the end's, `last`), and a subset killed by its timeout or
  cap one (`why`); a direct `check.sh` starts one more for `before`. (Corrected in place at the review: it said a lane's
  call started no more node, which holds only for a green one.)
- *Default:* `spec_entry` in `lib/spec.sh`, a decoder the feature list doesn't name, moves with the others.
- *Default:* the one queue decoder drops a CR at a line's end, as the queue view's reader always has. The runner's read
  didn't, so a hand-edited CRLF entry now starts with clean arguments rather than ones ending in a CR. No queue file the
  harness writes changes.
- *Default:* the runner's project read (`entry_project`) used `read -r`, which trims outer blanks, and took an empty
  entry's project from a glob that matched every project. Both now read the one decoder: a path with a blank at its end
  keeps it, as `harness start` always saw it, and an empty entry has no project, so neither run holds it.
- *Default:* an argument or an entry that isn't valid UTF-8 no longer keeps its bytes: node decodes both as UTF-8, so a bad
  byte becomes U+FFFD. Every other byte holds, by the comparison below. A brief or path in another encoding would show
  this; the harness writes none.
- *Default:* `harness queue add --continue` replacing an entry already queued (`cmd_queue` in `bin/harness`: `printf
  '%s\n' continue "$run" --queued --requested …`) stays as it is, a second writer of the format. It writes an option
  holding a newline raw, so that option reads back as several arguments. That is a bug on the base tree, kept because
  this move changes no queue byte; the one-line fix is Michael's question in the entry.
- *Default:* `control` (`lib/record.sh`) answers `run` itself when there is no `STOP` or `PAUSE` file and the first status
  line is exactly `status: run`, and asks `lib/inbox.mjs` for anything else. A helper-off coordinator then polls with no
  node start, as before the move (`node-memo`'s idle-poll check was red without it, found by the review's full suite).
- *Default:* `harness queue unpark` keeps its raw `mapfile`: it passes lines from one queue file to the next, and the
  encoder leaves a line holding 0x1f as it is.
- *Default:* the `sort -u` of the blocked ids stays in `lib/driver.sh`: it sorts by the driver's locale, and the end
  reason's bytes depend on it.
- *Default:* the three `if [[ -n $blocked ]]; then note "…"; ends+=("…"); fi` lines of the end block and the `printf` that
  joins `ends` stay in `lib/driver.sh`, though the feature names that composition as emptied: the second note proof
  compares from `note "` to the end of the line, so those lines keep their tails. `runEnd` answers the lists they read.
- *Default:* a status line's `stop` reason is cut where glibc's `[[:alnum:]]` starts it, by `[\p{Alphabetic}\p{Nd}]`. That
  matches bash on every fraction and superscript (`status: stop ½ done` gives `done`) but still takes 9,124 code points
  glibc's tables don't: combining marks, and letters newer than its tables. `[[:space:]]` matches glibc exactly. (The
  move had `\p{N}`, which took fractions too: fixed at the review.)
- *Default:* `harness continue`'s reset of a phone stop (`unstop`) rewrites INBOX.md as UTF-8, so a byte that isn't
  valid UTF-8 elsewhere in the file becomes U+FFFD, where `sed -i` kept it. The same holds for a `HARNESS_FAILED=` name
  that isn't valid UTF-8: its rerun would name a file that doesn't exist, so the red stands. The harness writes neither.
- *Default:* entries the harness never writes, planted by hand, read differently: `start` of `/` has no project (it was
  `/`), a run id with glob characters is read literally (the glob expanded it), `continue ../alpha/r1` matches nothing
  sensible (it was `alpha`), and the queue view gives a project for an unknown verb (it gave none).
- *Default:* moves 2 and 3 leave the bash barely shorter: 52 lines deleted and 51 added across `lib/lane.sh` and
  `lib/driver.sh`. A decision became a question and the read of its answer, and a read of labelled lines is a line too.
  What left the bash is the branching. This counts against the bash-removed row (150 or more), which S4-05 states.

## A question with no answer

A decision that was bash is a node call now: through the resident helper, and when that fails, by a plain spawn. Both can
fail (an OOM kill, no process slot, node gone), and an empty answer must then take the safe branch, not the one an empty
value happens to fall into. The review found the places where it didn't (`docs/plans/2026-11-07-S4-review.md`), and each
now has its branch and a check in `tests/checks/no-answer.sh`. That file's `node` wrapper refuses only the questions
named, as a killed spawn does, and logs each refusal. **The rule: no answer never starts, tags or ends anything it
couldn't have before. It waits for the next poll, or it takes the branch that puts a card in front of Michael.**

| The question | No answer now | Was, before the review |
|---|---|---|
| the queue poll's projects (`queue.mjs projects`, `lib/queue.sh`) | no entry starts this poll; `could not read the queued entries' projects: none starts this poll` in the runner's log | nothing held: a second run could start on a busy project |
| an entry's arguments (`queue.mjs decode`, `lib/queue.sh`) | a file with bytes stays queued; `could not read <entry>: it stays queued`. The decode now runs before the spec check | the entry went to `done/` and `harness` ran with no arguments |
| the round's verdict (`lane.mjs verify-round`, `verify`) | a milestone not done is the fail; a done one is thin, so its card | not done: `$short` unbound, so the lane crashed. Done: a fail with nothing failed, no card, and the lane verified again and again (127 rounds in one stub run) |
| the suite's effect (`lane.mjs suite-verdict`) | the round's result stands, and a red suite makes it red | neither tag nor card: verify ran again |
| the need and the card (`lane.mjs verdict`) | where `needs-<m>` exists: the need `verify <result> (see harness-log.md)`, the card `verify_<result>` (`verify_recheck` for a fail) | the lane closed `<m> needs Michael: ` with no card |
| the run's end lists (`lane.mjs run-end`, the driver's end block) | asked again at the next poll, three times, then the end the empty lists give | `no feature left to try`, at once. The base tree gave that on a dead node too: its `F summary`, `F parked` and `F blocked` were node |
| a reason's card and priority (`lane.mjs end-kind`, `finish`) | high priority, no card kind | normal priority |
| the stop's reason (`inbox.mjs stop-why`, `stop_why`) | `stopped by Michael` | an empty end reason |

Already safe, as the reviewer read them: `control` (run, until the next poll), `fix-round` (the card), `closed` (read as
the crash, its card), `lane-done` (`<m> needs Michael: its merge`, fail-closed), `before` (the full run), `guard` and
`last` (no rerun, no marker). None of these branches prints a new note: the runner's two lines are its `log`, and every
other branch ends in a note, card or exit line that was already there.
