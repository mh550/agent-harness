# The queue runner collects as it drains: gc --all-merged --deps per project, before the debrief

*(2026-10-25, run agent-harness-2026-10-25-lifecycle, feature L4-04; spec `docs/specs/2026-10-25-resource-lifecycle.md`
§L4 item 4, plan `docs/plans/2026-10-25-L4-gc.md` §4)*

- **Finding:** B8: gc is manual only. Merged worktrees, merged branches and the `node_modules`/`.next`/`.venv` of
  ended runs pile up night after night under `~/worktrees` until someone runs `harness gc` by hand.
- **Choice:** `lib/queue.sh`, on its exit path, after the tmux reap and only when it started a run, runs
  `harness gc <project> --all-merged --deps` once for each distinct `PROJECT_DIR` (from `meta.env`) of the state
  dirs whose `runners` holds its id. `runner.log` gets `gc <name>: harness gc <dir> --all-merged --deps`, then each
  gc output line as `gc <name>: <line>`; a non-zero exit logs `gc <name> failed (exit <n>)`, and the runner goes on to
  the next project and then the debrief, whatever gc did. gc's own guards decide what goes: never a live, queued or
  desk-open run's worktree or deps, never the project's checkout, local deletes `branch -d`. The debrief reads a
  removed worktree's run record from the ledger's copy (`rec_dir`). Only projects the runner started a run in: a
  project nobody ran tonight is Michael's to collect.
- **Rejected:**
  - **gc from the debrief:** the debrief is a read-only session (its never-list denies `git branch -d`, `git
    worktree`, …, and it is checked for writes); giving it gc would break the one guarantee that makes it safe.
  - **gc after the debrief:** the debrief is detached (`setsid`) and outlives the runner; a gc racing it would change
    the worktrees it is reading and be flagged as the debrief's write.
  - **gc after each run ends, inside the loop:** it would run while other projects' runs are going and the box is
    busiest, and again for every run of one project; once, as the queue drains, does the same work at a quiet time.

`timeout -k 10s ${HARNESS_GC_TIMEOUT:-10m}`, so a prompt or a hung network can't hold the debrief:
decisions/2026-10-26-gc-unattended-guards.
