# The unit tier: node evals become `node:test` files in one process, reported as the suite's PASS/FAIL lines

*(2026-11-03, run `agent-harness-2026-11-03-2`, U1-01 (the mechanism); U1-02 to U1-04 the move, U1-05 the measured
rows; spec `docs/specs/2026-11-03-unit-tier.md`; plan `docs/plans/2026-11-03-test-suite-redesign.md` phase 1)*

## Finding

108 `node --input-type=module -e` evals in 35 check files each start node (27 ms) and assert by exit code: a red one
says only that the eval exited 1. Node's own runner (`node --test`) runs any number of test files in one process under
`--test-isolation=none` (v22.8.0), prints `node:assert` diffs, and takes a custom reporter (an async generator over its
events, the API marked Stable). It has no list-only mode, so a test's names can't be collected without running it.
Under `--test-isolation=none` the runner imports every file into the one process, so a module that read `argv[1]` on
import would see the other test files: `lib/testcount.mjs` ran its CLI on `argv[2]`, the next test file, and printed
its count (U1-06's review), so it now runs its CLI only as a script, the guard every other `lib/*.mjs` has. A test's
`console.log` lands on the same stdout as the reporter, and a `process.exit(0)` ends the run with exit 0 and its
output unflushed: with no FAIL line and no non-zero exit, the tier would read `0/0 checks passed`, green. On node 24 a bare directory argument (`node --test tests/unit/`) is imported as a
module (`ERR_UNSUPPORTED_DIR_IMPORT`): the tier is named by its glob, `tests/unit/*.test.mjs`.

## Choice

- **`tests/unit/<module>.test.mjs`**, one per `lib/<module>.mjs` under test: `import { test } from "node:test"; import
  assert from "node:assert/strict"`, the module by a path relative to the test file, flat `test("<exact old check
  name>", …)` calls (no `describe`, no subtests: the name is the fixture's name). No test calls `process.exit`, writes
  outside `os.tmpdir()` or keeps module-level mutable state (one process serves every file). The first moved test is
  `testcount.mjs: the runner's last N/M checks passed is the count` (from `tests/checks/33-suite-runner.sh`).
- **`tests/unit/reporter.mjs`** (*default*: a reporter over a TAP parser in bash): `PASS <name>` per passing test (a
  skipped one `PASS <name> (skipped: <reason>)`, the suffix `tests/run.sh` already strips), `FAIL <name>` then the
  failure indented two spaces (an assertion's message, its diff; any other error its stack without `node:` frames);
  nothing for diagnostics or stderr, nothing else on stdout but, last, `# unit tier: <n> tests` from the run's own
  `test:summary` (the one with no `data.file`, emitted only when the run completes; U1-06, *default*).
- **`tests/checks/00-unit-tier.sh`** carries the tier into every full run: `node --test --test-isolation=none` (*default*)
  with the reporter over `${TEST_UNIT_DIR:-tests/unit}/*.test.mjs`, then its own `N/M checks passed`; exit 1 on a FAIL
  line or a non-zero node exit, and a non-zero exit with no FAIL line (a `process.exit` at import) prints
  `FAIL unit tier: node --test exited <rc> with no FAIL line`, so the runner's count is never all passed. Its own FAIL
  line too (U1-06, *default*: a red run is never green on zero tests) for no `*.test.mjs` in the directory, no summary
  line (`node --test ended without its summary (a process.exit?)`), and PASS/FAIL lines that aren't the summary's
  count (`a test wrote to stdout?`); it drops the summary line from what it prints. It does not
  source `tests/lib.sh` (no throwaway project). `TEST_UNIT_DIR` (*default*: one variable read by this file alone, as
  `TEST_CHECKS` points the runner elsewhere) lets `tests/checks/33-suite-runner.sh` run it on throwaway unit files.
- **`CLAUDE.md`** (*default*): the node floor is `node ≥ 22.8`; pure functions are unit-tested in
  `tests/unit/<module>.test.mjs` under `node --test`; "a pure function's behaviour gets a test in `tests/unit/`, not a
  stub run"; How to verify names the tier alone, `bash tests/run.sh 00-unit` and `--test-name-pattern`. Its check lives
  in `tests/checks/79-suite-length.sh`, a file `CHECK_KEY_MAP` already names for `CLAUDE.md` (*default*: the feature
  step put it in `33-suite-runner.sh`, which would have to join the map, so a Gotchas-only change would rerun it).
- The fixture `tests/fixtures/check-names.txt` stays the list of names: a moved check keeps its name, so a full run's
  conformance proves the move lost nothing.
- **A check that was an eval and a CLI run** (U1-02, *default*): the part its name describes keeps the name, the other
  part takes a new name (added to the fixture; no old name leaves it). In `tests/checks/12-journal-pure-e4-entrys.sh` the
  evals keep the names of validate, progress, the pack and the trim, and their CLI runs became `the render CLI …`, `the
  pack CLI …` and `journal: ingest prints trimmed summary 410 …`; the damaged-journal check is CLI behaviour and keeps its
  name, its eval became `entries.mjs: a summary can't open a code fence or an HTML block, and a 2000-character id …`. The
  validate CLI's two cases joined `journal: validate exits 2 when its only errors are the caps, 1 with any other`, the
  check already on that CLI, each now asserting exit 1.
- **A module's tests in its own file** (U1-02): `tests/checks/12-journal-pure-e4-entrys.sh`'s two `currentRules` evals
  went to `tests/unit/memlint.test.mjs`, not `entries.test.mjs`, one file per `lib/<module>.mjs`.
- **An eval run under `TZ=… node`** (U1-02, *default*): the test sets `process.env.TZ` and puts it back in a `finally`
  (node rereads the zone on assignment); the tests are synchronous, so no other test runs under that zone.
- **An old name keeps its bytes**, quoting artefacts included: two names of `tests/checks/51-view-pure.sh` hold a literal
  `'\''` (written inside bash double quotes), and their `test(…)` names hold it too.

- **No unit test reads a `CHECK_KEY_MAP` path** (`CLAUDE.md`, `prompts/`, `templates/`): `tests/checks/82-key-map-lint.sh`
  lints `tests/checks/` only and the map never names `00-unit-tier`, so such a test would go unrun on a partial run.
  A test may read `lib/` and `tests/fixtures/` (unmapped: a change there runs everything); `inbox.test.mjs` reads
  `lib/driver.sh`'s INBOX.md heredoc, as `57-inbox.sh` does, not a copy of it.

## Rejected

- **TAP parsed in bash**: the TAP text's version and stability aren't stated by the Node docs; the reporter API is
  Stable and the reporter is a few lines.
- **A second runner (Vitest)**: an npm package (the code rules allow none), and the survey's cost for ~110 tests.
- **Keeping the evals**: 108 node starts, and a red that says only "exited 1".
- **`--test-isolation=process`** as the default: a node start per file, and `--test-concurrency` would run files in
  parallel inside one check file's slot.
- **A count of the fixture's unit names in `00-unit-tier.sh`** (U1-06) in place of the summary line: the fixture is
  the full run's, and a `TEST_UNIT_DIR` run has none.
- **A collection pass for the names**: Node's runner has no list mode; the fixture stays, the reporter prints the names.
